# RFC 0003: Hash-collector symlink following (bounded, split from config discovery)

- **Status:** Implemented <!-- Draft | Accepted | Implemented | Superseded -->
- **Owner:** TBD
- **Date:** 2026-08-28
- **Affected crates/files:** dir_walker (`impls/ignore_real_dir_walker.rs`, `impls/real_glob_dir_walker.rs`), omni_collector (`collector.rs`, plus the `CollectorSys` bound); explicitly **not** omni_configuration_discovery
- **Prior art referenced:** Bazel (symlink handling in the action graph), Git (symlink following in `add`), GNU tar (`-h`/`--dereference`), the `ignore`/`walkdir` crates
- **Relationship:** Enhances RFC 0001 (Workspace Projections) and RFC 0002 (Projection Enhancements) but is **not** required by them. RFC 0002 ships a documented limitation with a `link: copy` workaround; when this RFC lands, that limitation lifts with no change to projection code.

## 1. Summary

The hash collector does not follow symlinks, so a **symlinked directory** in a project's input scope is skipped entirely — its contents never contribute to the project's input hash. When such a directory is a workspace projection (RFC 0001/0002 directory link), changes behind the link do not invalidate the consuming project's cache, so it serves stale output. This RFC proposes exposing `follow_links` on the directory walker and enabling it **only for the hash collector** (config discovery keeps it off, preserving the anti-injection guarantee), with a **containment bound** so that following a symlink cannot pull machine-external content into a cache key.

## 2. Motivation / Problem

Directory links are the natural output of RFC 0001's `namespaced` strategy and RFC 0002's `pattern`/`flatten` + `match-kind: dir`. They are materialized as `symlink`/`junction` by default. But omni's hash collector treats a symlinked directory as a non-file and skips it (see §4), so:

- A project whose `input_files` glob covers a projected directory hashes **nothing** from inside it.
- `omni projection sync --update` pulling a new git rev, or a local source edit, changes the projected content but **not** the consuming project's hash → the project is considered up-to-date and reuses stale cached output.

This is a **silent cache-correctness bug** — the worst class for a build tool. It is pre-existing (it applies to RFC 0001's `namespaced`/`explicit` directory links today), but RFC 0002's directory-glob routing makes directory links common, which is what motivates fixing it now.

The desired outcome: content reachable through a projected (or any) symlinked directory in a project's input scope participates correctly in that project's input hash, without (a) reopening the config-injection vector RFC 0002 §A.4 closed, or (b) making cache keys depend on state outside the workspace.

## 3. Goals / Non-goals

### Goals

- Make the **hash collector** follow symlinks so a symlinked directory's contents are hashed.
- Keep **config discovery** not following symlinks, preserving the RFC 0002 §A.4 no-injection guarantee.
- Preserve cache determinism: following a symlink must not incorporate content from **outside the workspace root** into a hash.
- Keep the `.gitignore`/`.omniignore` exclude valve working (RFC 0001 #14, RFC 0002 #7a) for in-workspace content a user does not want hashed.
- Bound the performance cost to symlink entries, leaving the per-file fast path untouched.

### Non-goals

- **No change to config discovery's traversal.** Manifests behind a symlink stay undiscovered by design.
- **No new projection config.** This is a collector/walker change; projections consume it transparently.
- **No general "follow links everywhere" switch.** Only the hash collector opts in.

## 4. Background: current mechanisms

Verified against the current source:

- **The walker (`crates/dir_walker/src/impls/ignore_real_dir_walker.rs`).** `IgnoreRealDirWalker` wraps `ignore::WalkBuilder`. `IgnoreRealDirWalkerConfig` (L14-36) exposes `standard_filters`, `hidden`, `ignore`, `git_ignore`, `git_exclude`, `git_global`, `ignore_case_insensitive`, `custom_ignore_filenames`, `overrides`, `filter_entry` — and **no `follow_links`**. `apply()` (L76-136) never calls `builder.follow_links(...)`, and there is **zero** `follow_links` usage anywhere in the crate, so the `ignore` default (`false`) always applies: symlinked directories are listed but never descended.
- **The collector (`crates/omni_collector/src/collector.rs`).** Uses `RealGlobDirWalker` (which delegates to `IgnoreRealDirWalker`). For each entry it prefers the cheap `d_type` and only stats symlinks/unknowns (L418-431). A symlinked **directory** resolves to `is_file == false` → `continue` (L433-435), and the walker never descends it. So the files inside a symlinked directory are neither enumerated nor hashed. Symlinked **files** are included (the stat follows the link) and their content is read through the link, so those hash correctly.
- **Config discovery (`crates/omni_configuration_discovery/src/configuration_discovery.rs`).** Uses the same `IgnoreRealDirWalker` (L44-60) with `follow_links` off. This is _desirable_ for discovery: RFC 0002 §A.4 depends on discovery not traversing symlinked directories, so a manifest planted inside a `symlink`/`junction` directory link is never loaded (no config injection).
- **The `filter_entry` seam.** `IgnoreRealDirWalkerConfig.filter_entry` (L34-49) already accepts a `Fn(&ignore::DirEntry) -> bool` predicate applied per entry; `ignore::DirEntry` exposes `path_is_symlink()` cheaply. This is the seam a containment bound would use.

Key fact the design relies on: RFC 0001 §4.7 ("input hashing follows symlinks") is only true for symlinked **files**; symlinked **directories** are skipped. RFC 0002 §6.5 corrects this.

### 4.1 Verified `ignore` 0.4.25 internals (the facts this RFC is load-bearing on)

The walker uses `ignore`'s **parallel** walker (`WalkBuilder::build_parallel`, `ignore_real_dir_walker.rs:175`), not `walkdir` directly, so the relevant code is `ignore`'s own `DirEntryRaw`/worker (`ignore-0.4.25/src/walk.rs`). Verified against the locked source:

- **Following resolves the target's type but preserves symlink-ness.** When `follow_links` is on and an entry is a symlink, the worker rebuilds it via `DirEntryRaw::from_path(depth, path, /*link=*/true)` (`walk.rs:1751-1758`), which calls `fs::metadata` — following the link — so the entry's `ty` becomes the **target** type (`Dir` for a symlinked directory) and `follow_link = true` (`walk.rs:384-415`). Consequently `file_type()` returns `Dir` and `path_is_symlink()` returns `true` via `self.ty.is_symlink() || self.follow_link` (`walk.rs:280-281`). This is exactly why the containment predicate can gate on `path_is_symlink()` and still fire for a followed link.
- **`filter_entry` controls descent, not just yield.** The predicate is applied in `generate_work` as `should_skip_filtered = !predicate(&dent)`, and the entry is only enqueued as `Work` (the unit of descent) when it is not filtered (`walk.rs:1789-1798`). Returning `false` for a symlinked-directory entry therefore prevents **both** yielding it and descending into it — the seam the bound needs.
- **Broken links are already graceful; loops are not.** A broken symlink makes `from_path`'s `fs::metadata` fail with `NotFound`, which is already swallowed by the existing `io_error()/NotFound` handler (`ignore_real_dir_walker.rs:182-188`). A **cycle** is different: `check_symlink_loop` yields `Error::Loop { .. }` (`walk.rs:1762-1764, 2038-2056`), which is _not_ an io `NotFound`, so the existing handler does **not** catch it and the collector's `res?` (`collector.rs:413`) would abort the whole hash. Only the loop case needs new handling.
- **Windows junctions are symlinks to this machinery.** Rust std classifies a junction as a name-surrogate symlink: `FileType::is_symlink()` is `is_reparse_point() && (reparse_tag & 0x20000000 != 0)`, and `IO_REPARSE_TAG_MOUNT_POINT` (`0xA0000003`) has that bit set (std 1.81 `sys/pal/windows/fs.rs:1046-1062`). So a junction takes the same `follow_links && is_symlink` path, yields `path_is_symlink() == true`, and is covered by the bound identically to a Unix symlink. This resolves the junction open question (§7) by construction; the cross-platform test only pins it.
- **Walk roots bypass `filter_entry`, yet a symlinked root is still descended.** The initial root paths handed to the walker are pushed straight onto the work queue (`walk.rs:1360-1400`) without going through `generate_work`, so `filter_entry` is applied only to entries discovered **during descent**, never to the roots themselves. Separately — verified empirically and in `run_one` (`walk.rs:1638+`) — a symlinked directory used _as a walk root_ **is** followed and descended when `follow_links` is on, so its contents are enumerated. The consequence for the bound: an escaping symlink used directly as a walk root would be descended, and its external children (plain files) would sail through the non-symlink fast path. The containment check therefore has to be applied to the walk roots separately, not only inside `filter_entry` (see §5.5). This corrects an omission in the original mechanism analysis, which assumed `filter_entry` alone would cover every followed symlink.

## 5. Proposed design

1. **Expose `follow_links` on the walker.** Add `follow_links: Option<bool>` to `IgnoreRealDirWalkerConfig` (and `RealGlobDirWalkerConfig`), and have `apply()` call `builder.follow_links(v)` when set. Default remains `false`.
2. **Enable it only in the collector.** `omni_collector` builds its walker with `follow_links(true)`; `omni_configuration_discovery` leaves it unset (`false`). The two walkers' opposite needs — correctness (follow) vs. anti-injection (don't follow) — are satisfied independently.
3. **Also expose `filter_entry` on `RealGlobDirWalkerConfig` (required for the bound).** The collector walks through `RealGlobDirWalker`, and today its `build_base()` hard-codes `filter_entry: None` (`real_glob_dir_walker.rs:50`), so the existing `filter_entry` on the _inner_ config is unreachable from the collector. The bounded option therefore needs `RealGlobDirWalkerConfig` to carry the predicate through to the inner `IgnoreRealDirWalkerConfig` — `follow_links` alone is not enough.
4. **Bound the follow to the workspace root (decided; see §6.6 / §7).** Use `filter_entry` to reject **any** symlink entry (file _or_ directory — Q2, Option A) whose canonicalized target escapes the workspace root, so following a link can never hash machine-external content. The predicate fast-paths non-symlinks (`if !entry.path_is_symlink() { return true }`) so only symlink/junction entries pay a `canonicalize`, leaving the per-file `d_type` fast path untouched. When a symlink is rejected, emit an observable **`trace::warn!`** (the `trace` crate — distinct plumbing from `log`) naming the link and its target, so the exclusion is diagnosable rather than silent. Three implementation constraints the research surfaced:
    - **The predicate runs on the walker's OS threads and must be `Fn + Send + Sync + 'static`**, so it cannot use the collector's async `fs_is_file_async`; it needs a **synchronous** canonicalize. Decided (Q1, Option C): widen `CollectorSys` with `FsCanonicalize` (and `'static`) and clone `sys` into the closure, canonicalizing both the root and each target through `sys`. The "keeps the seam mockable" argument does **not** hold today — `InMemorySys`'s canonicalize delegates to the real filesystem — so the justification is instead a single FS story (all filesystem access on one seam), capability/policy-layer routing, and future in-memory testability. The `'static` cost is one supertrait bound; every concrete sys already satisfies it, and the four `Collector::new` call sites compile unchanged.
    - **Canonicalize the workspace root once, up front, and compare canonical-to-canonical.** `ws_root_dir` (`collector.rs:102`) is passed in by callers (`hybrid.rs`, `project_hasher.rs`, `workspace_hasher.rs`, `cache_manager.rs`) and is not guaranteed to be symlink-free. If the root has a symlinked component, comparing a canonicalized target against a non-canonical root would wrongly reject in-workspace targets. The canonical root is computed once and reused by both the predicate and the walk-root filter (§5.5).
    - **The bound is recursive-safe for free.** `ignore` re-enters `generate_work`/`filter_entry` for every symlink at every depth, so a symlink nested inside an in-workspace target that itself points outward is caught at its own level — one per-link check suffices; no transitive-target walk is needed.
    - **On a canonicalize failure (e.g. a dangling link) the predicate returns `true`** (Q3), leaving the broken link to the walker's existing `NotFound` swallow; containment rejection is reserved for links that resolve _outside_ the root.
5. **Bound the walk roots too — they bypass `filter_entry` (§4.1).** The collector derives its walk roots from `topmost_dirs` → `get_dir`, which follows a symlink but returns the symlink's own path, so a walk can be rooted directly at a symlinked directory. Because the walker never runs the predicate on its roots, canonicalize each walk root and drop (with the same `trace::warn!`) any whose target escapes the workspace root **before** walking; when every root is dropped, skip the walk entirely (an empty root set is otherwise a walker error). This closes the escaping-root hole that `filter_entry` alone cannot reach.
6. **Handle loops gracefully (broken links are already handled).** As established in §4.1, broken links already fall through the existing `NotFound` swallow (`ignore_real_dir_walker.rs:182-188`); only `Error::Loop` needs new skip-with-trace handling so a single cycle in input scope does not abort the whole hash. The collector detects it with a small recursive matcher that unwraps `ignore::Error`'s `Partial`/`WithLineNumber`/`WithPath`/`WithDepth` wrappers.
7. **Keep `.omniignore` as the exclude valve.** In-workspace content a user does not want followed/hashed is excluded the usual way (RFC 0002 #7a).

## 6. Mandatory analysis

### 6.1 Existing mechanisms (reuse vs. extend vs. add)

- **`IgnoreRealDirWalker` / `RealGlobDirWalker`** — _extended_ with one optional `follow_links` field; no new walker. `RealGlobDirWalkerConfig` additionally _exposes_ the already-present inner `filter_entry` (today discarded at `real_glob_dir_walker.rs:50`).
- **`filter_entry`** — _reused_ verbatim for the containment bound; the predicate seam already exists on the inner config and only needs plumbing through the glob config.
- **`omni_collector`** — _extended_ to opt in; the entry loop already stats symlinks, so the incremental change is small.
- **`omni_configuration_discovery`** — _unchanged_ (stays `false`), by design.

### 6.2 Maintenance cost

- One new optional walker field, threaded through two config structs and `apply()`.
- A `filter_entry` predicate in the collector (canonicalize-on-symlink + workspace-root prefix check) if the bounded option is chosen.
- A documented invariant: config discovery must stay `follow_links=false` (already pinned by RFC 0002 §A.4's discovery test).
- No new runtime dependency.

### 6.3 Testability

- **Walker unit tests:** `follow_links` on/off; a symlinked directory is descended when on, skipped when off; a `filter_entry` predicate returning false blocks both yield and descent. _(Implemented in `real_glob_dir_walker.rs`, `#[cfg(all(test, unix))]`.)_
- **Collector tests:** a symlinked directory in input scope contributes its contents to the hash and to resolved input files; editing/adding a file behind the link changes the digest; an escaping symlinked directory is excluded both as a descendant **and as a walk root**; an escaping symlinked file is excluded while an in-workspace symlinked file is kept. _(Implemented in `collector.rs`, `#[cfg(unix)]`.)_
- **Loop safety:** a symlink cycle in input scope is skipped, not fatal; a dangling link is skipped. _(Implemented.)_
- **End-to-end:** `omni hash -r project` changes when content behind an in-workspace symlinked directory changes, and stays stable when content behind an escaping symlink changes. _(Implemented in `tests/omni-tests/src/hash-symlink.e2e.spec.ts`.)_
- **Regression:** config discovery still does not enumerate a manifest inside a symlinked directory (the RFC 0002 §A.4 pinning test must stay green).
- **Cross-platform:** the implemented symlink tests are `unix`-gated (they create symlinks directly). Windows junction coverage behind `#[cfg(windows)]` is **deferred**; junctions are covered by construction (§4.1, decision #7) but not yet pinned by a test on Windows.

### 6.4 Integration points

- `dir_walker`: `IgnoreRealDirWalkerConfig`/`RealGlobDirWalkerConfig` (+`follow_links`; +`filter_entry` plumbed through `RealGlobDirWalkerConfig::build_base`), `apply()`.
- `omni_collector`: walker construction (`collector.rs:404-410`) opts into `follow_links(true)` and installs the bound predicate; the walk roots (`topmost`) are canonicalize-filtered before the walk to bound roots that bypass `filter_entry` (§5.5); entry-loop error handling swallows `Error::Loop`; `CollectorSys` (`collector.rs:53-57`) gains `FsCanonicalize` (and `'static`) for the sync canonicalize inside the predicate.
- Ordering: purely within the collection walk; no config-load or graph ordering change.

### 6.5 Potential regressions

- **Workspace-wide cache invalidation (one-time) — no migration surface pre-release.** Enabling following changes input hashes for any project with an in-workspace symlinked directory in scope (its contents start counting) and drops escaping symlinked files (Q2/Option A). In a released tool this would warrant migration notes; **omni is not yet released, and the current workspace has no hashed input symlink files**, so there is no existing cache to invalidate and nothing to message. Migration messaging is therefore dropped (former Q3; see decision #11). The change remains **not** purely additive in principle, but the practical blast radius today is zero.
- **Determinism.** Unbounded following lets an escaping symlink (including one a git source ships nested inside a projected directory) pull external, machine-specific content into a cache key → non-reproducible caches. The **bounded** option removes this by construction; the unbounded option relies on user `.omniignore` vigilance (weak when the user did not author the link).
- **Performance.** Following adds a canonicalize per **symlink** entry (bounded option); it does not touch the per-file `d_type` fast path the collector was tuned for. Symlink counts are orders of magnitude below file counts, so amortized cost is small — but a workload with pathologically many symlinks in scope should be measured.
- **Escaping symlinked _files_ change behavior under the bound (decided: Option A).** Today an escaping symlinked _file_ in input scope is hashed (its target content is read through the link). Applying the bound to **all** symlink entries — not just directories — means such a file is now **excluded** from the hash. This is the chosen behavior (Q2, Option A): it removes machine-external content from the cache key uniformly, so "nothing outside the workspace root enters a cache key" is a clean invariant rather than a dir-only rule with a file-shaped hole. The trade-off accepted: it is a genuine behavior change beyond symlinked directories (part of the one-time invalidation) and it narrows RFC 0001 §4.7's file-following promise for the _escaping_ subset. Two things make this acceptable — escaping-file content was already non-deterministic across machines, and the rejection is surfaced via `trace::warn!` so it is observable, not silent. Symlinked files whose targets stay _inside_ the workspace are unaffected.
- **Loop / broken-link handling.** Broken links are already graceful (§4.1); a `Error::Loop` must be swallowed as skip-with-trace, or a single cycle aborts the hash.

## 7. Open questions

_All open questions are resolved; see the resolution notes below and the decision log (§8)._

> **Resolved — Q1 (bounded vs. unbounded following): _bounded_.** Containment via `filter_entry`, gated on `path_is_symlink()`. The research confirms the cost lands only on symlink/junction entries (the non-symlink fast path is untouched), the bound is recursive-safe, and it covers Windows junctions identically (§4.1), so determinism holds by construction on both platforms. The alternative (unbounded) is rejected: it lets escaping links pull machine-external content into cache keys, producing cross-machine non-determinism — the severe, silent class of cache bug — and relies on user `.omniignore` vigilance for source-shipped links the user did not author. Bounded's opposite failure mode (silently excluding content a user intended to hash via an out-of-root link) is deterministic and observable (a rejection `trace::warn!` is emitted), which for a build tool is strictly preferable. A benchmark on a pathologically symlink-heavy workload is still worth running before release but is not blocking. See decision #3.

> **Resolved — Q2 (bound scope): _Option A — bound all symlink entries, files and directories_.** The bound applies uniformly to any symlink/junction whose canonicalized target escapes the workspace root, so escaping symlinked _files_ (hashed today) are now excluded alongside escaping symlinked directories. Rationale: a single clean invariant ("nothing outside the workspace root enters a cache key") beats a dir-only rule that knowingly leaves a non-determinism hole for files. Symlinking an out-of-workspace file into the workspace is a genuine edge case that users should avoid; the escaping case is surfaced via `trace::warn!` (see decision #9) so it is observable rather than silent. See decision #10.

> **Dropped — Q3 (migration messaging).** omni is not yet released and the current workspace has no hashed input symlink files, so there is no existing cache to invalidate and no migration to communicate. Revisit only if a hashing-semantics change ships after release. See decision #11.

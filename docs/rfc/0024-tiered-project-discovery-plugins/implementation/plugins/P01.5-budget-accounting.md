# P01.5: Discovery budget accounting

For implementers of the host, inference cache and runtime adapter. This design
applies [§8.1](../../008.00-performance-and-shared-safeguards.md#81-shared-safeguards),
[§8.2](../../008.01-inference-cache-and-storage.md#82-shared-storage-separate-task-and-inference-caches)
and [§17.2](../../017.00-review-findings-and-prerequisites.md#172-frozen-claims-do-not-imply-frozen-filesystem-inputs).
It specifies what to count, not public settings, wire fields or calibrated
defaults. P15 calibrates the [§8.4 candidates](../../008.03-tier-specific-enforcement.md#84-tier-specific-enforcement).

## Owners and lifetimes

| Owner and lifetime | What it limits | When it releases or resets |
| --- | --- | --- |
| Command, shared across activations and passes | Absolute host deadline and cancellation; actual discovery work, including scans, reads, bytes, parsing, cache validation, query work and final revalidation; aggregate hook execution allowance, physical attempts and restarts | Work already performed is never refunded during the command |
| Activation, within the command | Its share of attempted hook and host-service work, subordinate to the shared ceilings | Does not reset across batches or passes |
| Host queue, workers and runtime pool | Simultaneous queued/in-flight requests and resident memory, including frozen views, decoded results and pooled runtime instances | Release only when the guarded work or retained allocation is gone; shared backing data is reserved once for its full lifetime |
| Physical hook attempt | Per-batch read bytes, transport input/output, per-instance runtime memory, fuel or other tier-specific limits, and an independent per-batch execution deadline | Release only attempt-local capacity at completion. Retained or handed-off allocations keep or transfer their reservations. A child attempt does not replenish aggregate budgets. |
| Logical result and pass-private staging | Each root-oriented result (or singleton result), including bounded contribution/state sizes and counts, and the combined accepted project/task/claim counts | Count once when accepted into private staging; discard that state on pass rejection without refunding attempted work |

Use checked reservations before admitting queued work, buffering or decoding
data, or committing accepted counts. Reserve against both applicable shared and
narrower limits; a failed reservation admits no work. If the exact size is not
known in advance, bound the read or decode as it progresses. For cumulative
work, commit what actually ran even if the attempt fails; release only unused
reservations. For resident memory, hold the reservation as long as the bytes are
retained, including across stage boundaries. An implementation may charge
multiple dimensions for one operation (for example, read bytes and decoded
memory); do not count the same activity twice in the same dimension.

Cache lookup and validation use the host deadline and do not spend a
per-hook allowance. Before dispatch, give each hook the earliest of its
per-batch deadline, the shared command execution deadline and the host
deadline. Start the shared execution deadline at first live dispatch, keep
it across concurrent workers and passes, and do not create it on a cache-only
pass. A hook's batch clock starts at dispatch and includes time spent
waiting for its host calls. During a hook,
enforce the per-batch read limit on bytes supplied by host reads, including
bytes from captured inputs. Charge actual filesystem I/O and capture memory
to their shared host counters.

## Scheduling and failure

- **Cache hits use host budgets.** Charge actual index lookup, record reads,
  decoding, evidence and query validation, and retained memory. An invalid
  record that becomes a miss still cost work. A hit takes no hook fuel or
  execution time for a hook that did not run, but remains subject to host
  deadlines and cancellation. Host budget exhaustion is fatal, not a cache
  miss. Apply the same logical result limit to cached
  and live roots; cache decoding is bounded separately from hook transport.
- **Split only trusted aggregate transport overflows.** After cancelling or
  finishing the failed attempt and releasing its buffers, partition the ordered
  roots deterministically. Spend an attempt from the same command ledger
  before dispatch. Children use the same frozen stage and input view. A
  logical-limit violation, denial, trap, cancellation, deadline or malformed
  result is not a split signal. An oversized singleton or indivisible root
  fails without splitting. Failed attempts consume work but accept no results.
- **Restarts are separate and default off.** If enabled, only detected
  concurrent input changes can restart the pass. Start a fresh
  input view and semantic session, using the remaining original work and
  deadline budgets. Discard rejected results and notices; publish neither.
  Revalidate any cache hit in the new view. A restart resets private logical
  counts, not attempts or spent work. Cancellation stops the entire command.

## Worked checks for P06.7, P07 and P08

Use small fixture-local limits, not production defaults:

| Case | Given | Expected |
| --- | --- | --- |
| Mixed cache/live | Pass cap: 3 tasks. Root A restores 2 tasks. Root B's live result contains 2; each root passes its own cap. | Reject the combined result. A costs host validation, no hook time; B costs actual hook and host work. Neither root adds reusable output. |
| Reduced root cap | A cached result contains 3 tasks; this pass permits 2 per root. | Do not restore the record. A bounded live miss may produce a new result, also subject to the cap of 2; actual validation work is not refunded. |
| Retained runtime | Resident cap: 10 units. A pooled instance retains 4. Two workers concurrently request 4 units each. | At most one reservation succeeds while the pool retains its 4 and the first worker holds its reservation. Completing a hook or handing off a decoded buffer does not free retained memory. |
| Successful split | Attempt cap: 3, including initial dispatch. `[A, B]` hits a trusted aggregate transport limit after doing work. `[A]` and `[B]` succeed. | Charge 3 attempts and all actual work. Accept each root once; publish only after both stage and pass validation. With a cap of 2 there is no third dispatch and the incomplete stage is rejected. |
| Not a split signal | `[A, B]` returns guest error text saying it exceeded a size limit. | Fail without splitting; guest text is not a trusted overflow classification. |
| Detected change | Command work cap: 10 units. The first pass used 7 before final validation detected an input change. | With restarts off: reject. With one enabled restart: only 3 units and the remaining original time are available, with no carried-over results or notices. A second mutation cannot start a third pass. |

P15 should sweep batch size and concurrency with cold, warm and mixed hits;
measure host work and peak resident memory separately from dispatched hook time.
Sweep skewed root sizes and a split/retry workload so limits do not hide
allocation peaks or failed-attempt costs.

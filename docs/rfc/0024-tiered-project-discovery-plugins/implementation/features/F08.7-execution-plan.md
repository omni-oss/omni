## Slice A (step 1b): keyed lease dedupe

**Slice 1 of the PR.** Small; High risk (shared concurrency primitive used by install, generator,
tool and projection paths).

### Change

- `SourceLease` keeps the `(kind, slug, pin)` identity it was acquired with. The
  identity is the on-disk slug `SourceLease::path` already validates; add it to the
  struct in `acquire` only (`try_acquire_exclusive` keeps returning a bare guard).
- `LeaseSet` holds `SourceLeaseInner { leases: Vec<Arc<SourceLease>>, keys:
  HashSet<(String, String, String)> }` behind its `Arc<Mutex<..>>`.
  - `hold` inserts the key first; only a new key is pushed. A duplicate `Arc` is
    dropped immediately, which closes its duplicate descriptor. This keeps the
    existing `hold(Arc<SourceLease>)` signature, so no caller changes.
  - `absorb` takes the other set's leases and keys, inserting each key and dropping
    duplicates. It still empties the source set. It never holds both mutexes at
    once (take, release `other`, then lock `self`, as today) and keeps the
    `Arc::ptr_eq` early return, so two sets absorbing each other cannot deadlock.
  - `len()` returns the number of held (distinct) leases. `is_empty()` unchanged.
- No change to `materialize_into`: it still acquires a lease every time and hands it
  to `hold`; the set decides whether to keep it. Peak descriptors stay "distinct
  set + one", and dropping a duplicate cannot release the kept handle's `flock`-style
  lock (separate open file descriptions).
- Doc comment on `LeaseSet`: `len` is the number of distinct checkouts, not the
  number of materializations.

### Failing-first tests

In `crates/omni_remote_source/tests/store.rs`, extending
`a_lease_set_protects_every_source_until_the_last_handle_drops` or a sibling:

1. Materialize the same source twice into one set: `len() == 1` (fails today with 2),
   two equal roots, and one prune reports it `skipped_in_use`.
2. Materialize two different commits of one repository into one set: `len() == 2`.
3. `absorb` a set holding the same checkout: target `len()` unchanged, source empty,

4. Drop the target and prune: the checkout is removed. This passes on today's code
   too; it is a guard that the new keyed path does not accidentally keep a dropped
   duplicate alive, not a failing-first test.

Labels: tests 1 and 3 are failing-first; 2 and 4 are regression guards. The
existing distinct-source test keeps its assertions.

## Slice B (step 3): prune reads registrations and references

**Slice 2 of the PR.** Large; High risk. Requires steps 1a (merged) and 2 (merged).

### Reader

New crate-private module `crates/omni_remote_source/src/protection.rs` (registered in
`lib.rs`). It owns the tolerant reader and the read policy. Because it is a sibling of
`manager`, it takes its inputs as arguments: `&self.drivers`, `&self.sys`, the store
root and the caller's own `refs_dir()`. It needs no new accessor on the manager.

- `type ReferenceKey = (String, String, String)` — `(kind, store slug, pin)`.
- Read policy: **every filesystem call in the reader** — directory listing, the
  `refs/` metadata probe and file reads — goes through one crate-private `ReaderFs`
  trait (blanket impl for `TSys: RemoteSourceSys`) wrapped in `with_timeout`. **3
  attempts in total**, with 10 ms then 25 ms sleeps between attempts, and a 5 s
  timeout per attempt (a policy value the unit tests shorten). A **timeout ends the
  call at once and is not retried**; it is classified as `ReadError::Timeout`.
- Retry classes:

  | Error | Retried |
  | --- | --- |
  | `NotFound` from listing `<store>/workspaces/`, listing a `refs/` dir, or the `refs/` metadata probe | **no**: these are values, not errors (empty registry / no references / not live) |
  | any other `io::Error` from a read, list or metadata call (`PermissionDenied`, `WouldBlock`, `Other`, `Interrupted`) | yes, up to 3 attempts |
  | `NotFound` from reading a **file that was just listed** (a concurrent `forget` or cleaner) | yes, up to 3 attempts, then fail closed naming the file |
  | timeout | no, immediate `ReadError::Timeout` |
  | parse, hash/path mismatch, unknown field/version, non-absolute path, unsafe pin | no, deterministic |
- `tokio::time::timeout` abandons the await but cannot cancel an in-progress blocking
  filesystem call; that residual thread is stated in the PR.
- `ReaderFs` has a `ScriptedFs` test double that implements only `ReaderFs` (not
  `RemoteSourceSys`, so the blanket impl does not overlap). The scripted tests live
  in `protection.rs` under `#[cfg(test)]`, not in `tests/store.rs`, so they can reach
  the crate-private seam. The reader functions take `TSys` (for
  `&DriverRegistry<TSys>`) and `F: ReaderFs`; the implementer confirms the blanket
  impl does not overlap at compile time. The shortened
  timeout/attempts are a `ReferenceReadPolicy` argument, not a manager field. Retry,
  timeout and stop are unit tested without a FIFO or a real hang. This slice also
  removes `FakeDriver::slug`'s `file_name().unwrap()` and states the no-panic
  contract on `SourceDriver::slug`: `k` failures then success (attempt count),
  a parse error (one attempt), an `Other`/`Interrupted` I/O error (retried), a hung
  list, a hung metadata probe and a hung read (one attempt, `Timeout`), probe
  `NotFound` → not live after one call, listing `NotFound` → empty, file-read
  `NotFound` × 3 → fail closed, and file-read `NotFound` then `Ok` → data.
- `read_registration_dir`: list `<store>/workspaces/`; `NotFound` is an empty
  registry (a value, one call), any other error is a failure, never an empty
  registry. For each `*.json`:
  parse with `RegistrationData::from_file_bytes` (hash/path mismatch, unknown fields
  and newer versions fail naming the file). A `lockfile_path` that is not absolute is
  a corrupt registration (fail closed), never a path resolved against the pruner's
  working directory. Then probe `lockfile_path.parent()/refs` with
  `fs_metadata_async`:
  - `NotFound` → not live for this run, registration left on disk;
  - `Ok` or any other error → live (uncertainty keeps protection);
  - live: read that directory tolerantly.
- `read_reference_dir`: list the directory (`NotFound` → no references, a value,
  one call; any other error → failure). If the probe said `Ok` and the listing then
  says `NotFound`, the directory vanished in between: it reads as not live, so that
  registration protects nothing for this run. This accepted race is pinned by a
  `ScriptedFs` case and stated in the PR. For each `*.json`, parse `RefSetData` **without**
  `check_kind`/`prepare_ref_set`/`reconcile_pins`. For every `kind → locator →
  selector → {pin}`:
  - pin that fails `is_safe_segment` → fail closed, naming the file;
  - kind with no registered driver → ignore (the store lists only registered kinds);
  - otherwise build `SourceSpec { locator, selector, connection:
    Connection::new(locator) }` and map through the pruner's own driver:
    `safe_slug(driver.slug(&spec))`. The selector is required because a custom
    driver's slug may depend on it; the connection is a placeholder, so `slug` must
    be a pure function of `(locator, selector)` and must not read `connection`. This
    slice owns the `SourceDriver::slug` doc comment and the slug-contract paragraph
    in `docs/patterns/source-kinds.md`; Slice E owns that file's lines 14 and 63 and
    its leases/prune section.
- **Absolute paths only.** Step 2's `normalized_lockfile_path` falls back to the
  parent as given when canonicalization fails, so a caller that configured a
  relative `lockfile_path` could store a relative registration, which this reader
  rejects and which would then refuse every consulting prune of the whole store.
  The writer therefore converts the parent with `std::path::absolute` before
  canonicalizing, and if the result is still not absolute it skips registration with
  a warning (the same downgrade as a newer layout) while still writing references.
  Canonicalization stays at the async call site; the path assembly becomes a pure
  `fn normalize_lockfile_path(absolute_or_canonical: &Path) -> Option<String>` with
  unit tests (relative → `None`, absolute → `Some`).
- The caller's own `refs_dir()` is always read too, whether or not it is registered,
  so `--unused`/age from a workspace installed by an older omni never deletes its own
  checkouts. Route it through `std::path::absolute` like the registration paths, so a
  relative `lockfile_path` config cannot silently read the wrong directory.
- `refs.rs`'s module/type doc ("Store pruning does not consult reference sets") is
  corrected in this slice.

Any error here is returned as `Error::custom(message)` naming the file and is a
refusal for the consulting flags.

### Prune loop

- F08.7's "initial pass" is the dry run. The CLI always performs one before
  confirming, so the dry run is also the early refusal pass; a direct real-run
  caller gets per-entry fail-closed handling only.
- Dry run: when `consults_references()`, build the protected set once, before
  reporting anything. A parse, persistent read or timeout error refuses the whole
  run. An entry in the set is reported in `skipped_referenced`, never in `removed`;
  the existing lease probe still reports `skipped_in_use` and wins on ordering
  (lease first, then reference).
- Real run: the whole reference path is gated on `consults_references()`. When it is
  false (`--all`, or `include_referenced: true`), no `ReaderFs` call happens and the
  run behaves exactly as today. When it is true there is **no initial protected set
  and therefore no refusal pass**. Per entry, keep the current remote lock →
  exclusive try-lease order, and **while still holding both** re-scan registrations
  and the workspace's own refs, then skip the entry if it is now referenced. A cached set is not enough: this is where a
  registration written after the dry run protects the checkout (test 11 targets
  exactly this, with no test hook). A corrupt or unreadable registry therefore marks
  each selected entry `failed` and deletes no checkout; an empty selection exits
  successfully without discovering the corruption. The dry run is the refusal pass
  the CLI always performs.
  - Re-read failure: skip only that entry and report it in `failed` with the reason,
    never in `removed`. A timeout additionally stops per-entry re-reads for the rest
    of the run. `RegistryState` and the per-entry decision (`recheck_entry`, generic
    over `ReaderFs` and taking the lease probe as a closure) live in `protection.rs`
    so tests can drive them with `ScriptedFs`; `prune_store_report` holds one local
    instance, never a manager field, so a dry-run timeout cannot poison the later
    confirmed call;
    every remaining entry skips **only the reference re-read**: the lease probe still
    runs first, so a leased remaining entry is `skipped_in_use`; only unleased
    entries are reported in `failed` with the one cause. A hung mount cannot stall
    N × 5 s.
  - A referenced entry returns its guards without deleting; the exclusive lease is
    released, the tree stays.
- The existing store-wide `.pending` sweep still runs before selection, for a dry
  run and a real run alike. It is not gated by the registry read and removes only
  abandoned publication leftovers, never checkouts. Tests that say a corrupt
  registry "deletes no checkout" still allow the sweep to remove `.pending` paths.
- The no-git guard test `the_store_core_does_not_depend_on_git` currently scans only
  `default_impl.rs`; extend it to `protection.rs` so the new reader cannot name a
  concrete driver or the git crate.
- `prune_entry` changes from `Result<bool>` to `Result<PruneEntryOutcome>` with
  `Removed`, `InUse`, `Referenced` and `Failed(String)`, so the loop can route each
  entry to `removed`, `skipped_in_use`, `skipped_referenced` or `failed`.
- The in-lock re-read reads each registration and each of its reference files once
  per entry, not once per reference.
- Lock order is unchanged: install takes remote lock → shared lease → advisory lock;
  prune takes remote lock → try-lease → lock-free reads. Prune never takes the
  advisory lock and never waits on a lease.

## Slice C (step 4): `--unused` and the report

### Change

## Residual risks (carried into the PR)

- **One bad registration blocks the consulting flags for everyone.** A corrupt,
  newer-version or unreadable live registration makes every `--older-than`,
  `--larger-than` and `--unused` run fail until the file is fixed. Only `--all`
  escapes. This is the designed fail-closed behavior; the PR and the guide say so.
  Until step 4 the API sets `include_referenced: true` for age and size, so no CLI
  or API caller reaches the reader yet; the failure mode becomes user-visible with
  `--unused`, and the PR body says so.
- **`slug` becomes a persisted contract.** A driver whose slug changes between omni
  versions silently stops matching old foreign references, so those checkouts become
  prunable. The contract is documented in the pattern file and the driver trait.
- **A relative registration written by the already-merged step 2** (before the
  writer fix) is possible only when `fs_canonicalize_async` fails after
  `ensure_lockfile_parent` created the directory, which is rare. It hashes to a
  different file name than the absolute form, so the fixed writer never overwrites
  it. It refuses every consulting prune until removed by hand; the guide says to
  delete it under `<store>/workspaces/`.
- **A `NotFound` reference directory is treated as not live.** An unmounted
  workspace drive looks like a removed workspace, so its checkouts become prunable
  with no signal. The F08.7 failure-mode row "Transient unreadable directory ...
  treated as live" holds only for permission/read errors (which fail closed); Slice E
  corrects that row, and the guide says the unmount case looks like a move.
- **A registration deleted between listing and reading** (a cleaner or a later
  `forget`) refuses the consulting run after the 3 attempts rather than skipping it.
- **Timeouts are per call, with no overall deadline.** A slow but not hung mount can
  still hold the remote lock and take minutes across entries and registrations.
- **The re-read is O(selected entries × registrations × reference files)** per run,
  under the remote lock, and is not sized. Measure it with many checkouts and
  registrations before step 5; the accepted cost buys the no-gap guarantee.
- **`driver.slug` now runs on untrusted reference content.** Drivers must be total
  and panic-free on any locator. Either wrap the call in `catch_unwind` and treat a
  panic as fail-closed, or state the no-panic contract and fix `FakeDriver::slug`'s
  `file_name().unwrap()` before the selector test uses it. Step 3 picks the latter
  and documents it in the driver contract.
- **Timeout cannot cancel a hung syscall.** `tokio::time::timeout` abandons the
  await; the blocking thread may stay until the call returns. The run fails closed
  and stops re-reading, but one thread remains.
- **Older omni deletes referenced checkouts with no signal.** D1 decided no
  `VERSION` bump, so a mixed-version store can lose a checkout a newer workspace
  references. The release note and the prune help say so.
- **Registrations accumulate.** Removed worktrees and ephemeral CI workspaces leave
  tiny registration files until the follow-up `workspaces list/forget` command
  exists; `--all` still frees the checkouts.
- **Unregistered workspaces stay unprotected.** Workspaces that never wrote
  references (older installs, targeted projection syncs) are protected only while a
  lease lives.
- **The 5 s production timeout value is not exercised**; the same policy is unit
  tested at a short value with `ScriptedFs`. A persistent `NotFound` fails closed.
- **Windows** retry, replacement rename and delete-while-held are tested only by CI
  (if at all); local verification is Linux.

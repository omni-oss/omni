## Assessment

- **Kind:** Large overall (the F08.7 assessment stands). The slices differ in size:
  1b is Small, step 3 is Large, step 4 is Medium, step 6 is Small (documents).
  All are executed solo, one PR at a time.
- **Risk:** **High.** Deletion and retention in the shared store, a persistent
  format, cross-process concurrency and a behavior change guarded by several flags.
  Caching and directory walking are repo-level High-risk areas; this change reads
  `workspaces/` and `refs/` and deletes `trees/`.
- **How much changes:** 1b touches `lease.rs` and its callers' tests only. Step 3
  adds a reference reader to `omni_remote_source`, extends `StorePruneFilter`,
  `PruneReport` and the prune loop, and changes the API handler plus its response.
  Step 4 adds one core field, the CLI flag and output, the API request field, the
  generated command reference and e2e cases. Step 6 edits four documents.
- **How much is unknown:** the foreign-reference mapping (a custom driver's slug may
  depend on the selector), the failure/timeout behavior under a hung mount, and
  Windows replacement-rename/open behavior. The first is resolvable with the existing
  `fake_kind` driver; the last cannot be tested locally and goes on the release
  checklist.
- **How hard to undo:** each PR reverts alone. Reverting step 3 leaves registration
  files that older readers ignore. A wrongly pruned checkout is refetched (offline
  use breaks until re-install).
- **People and time:** one author, two independent plan reviewers, two independent
  code reviewers and CI per PR. Sequential because step 4 builds on step 3 and step 5
  builds on 4.
- **Unknown that could invalidate the plan:** if the reference reader cannot map a
  foreign reference through the pruner's own drivers without widening the driver
  trait, or if the per-entry in-lock re-read needs a new store lock. Neither is
  expected: `DriverRegistry::get`, `safe_slug` and `SourceSpec` are already public to
  the crate.
- **Checks:** `cargo test -p omni_remote_source` (steps 1b, 3, 4), `cargo test -p
  omni_api` (3, 4), `cargo test -p omni_remote_source_contributors` (1b), scoped
  clippy and rustfmt, the remote-sources e2e suite for step 4, and `bun run
  gen:refdocs` for the generated command page. Real-filesystem tests only; no mocks
  for deletion.
- **Next step:** two independent plan reviews (`github-copilot/claude-opus-5.5`,
  `github-copilot/gemini-4-neon`), then explicit build approval.
- **Escalation:** stop and re-plan if a slice changes the store layout, the lock
  order, or the wire format beyond the additive fields listed here.

## Slice A (step 1b): keyed lease dedupe

**One PR.** Small; High risk (shared concurrency primitive used by install, generator,
tool and projection paths).

### Change

- `SourceLease` keeps the `(kind, slug, pin)` identity it was acquired with. The
  identity is the on-disk slug `SourceLease::path` already validates; add it to the
  struct in `acquire` only (`try_acquire_exclusive` keeps returning a bare guard).
- `LeaseSet` holds `SourceLeaseInner { leases: Vec<Arc<SourceLease>>, keys:
  HashSet<(String, String, String)> }` behind its `Arc<Mutex<..>>`.
  - `hold` inserts the key first; only a new key is pushed. A duplicate `Arc` is
    dropped immediately, which closes its duplicate descriptor. This keeps the
    existing `hold(Arc<SourceLease>)` signature, so no caller changes.
  - `absorb` takes the other set's leases and keys, inserting each key and dropping
    duplicates. It still empties the source set.
  - `len()` returns the number of held (distinct) leases. `is_empty()` unchanged.
- No change to `materialize_into`: it still acquires a lease every time and hands it
  to `hold`; the set decides whether to keep it. Peak descriptors stay "distinct
  set + one", and dropping a duplicate cannot release the kept handle's `flock`-style
  lock (separate open file descriptions).
- Doc comment on `LeaseSet`: `len` is the number of distinct checkouts, not the
  number of materializations.

### Failing-first tests

In `crates/omni_remote_source/tests/store.rs`, extending
`a_lease_set_protects_every_source_until_the_last_handle_drops` or a sibling:

1. Materialize the same source twice into one set: `len() == 1` (fails today with 2),
   two equal roots, and one prune reports it `skipped_in_use`.
2. Materialize two different commits of one repository into one set: `len() == 2`.
3. `absorb` a set holding the same checkout: target `len()` unchanged, source empty,
   and the checkout still protected until the target drops.
4. Drop the target and prune: the checkout is removed (no leaked duplicate handle
   keeps it alive). This is the regression that would catch a dedupe that forgets to
   drop the duplicate.

The existing distinct-source test keeps its assertions.

### Checks and undo

`cargo test -p omni_remote_source`, `cargo test -p
omni_remote_source_contributors`, `cargo clippy -p omni_remote_source -- -D warnings`,
`cargo fmt -p omni_remote_source -- --check`. Undo: revert the PR; leases become
unkeyed again, with no format or on-disk change.

## Slice B (step 3): prune reads registrations and references

**One PR.** Large; High risk. Requires steps 1a (merged) and 2 (merged).

### Reader

New crate-private module `crates/omni_remote_source/src/protection.rs` (registered in
`lib.rs`). It owns the tolerant reader and the read policy; the manager calls it.

- `type ReferenceKey = (String, String, String)` — `(kind, store slug, pin)`.
- Reads retry up to 3 times with short sleeps (10 ms, 25 ms) and a 5 s
  `tokio::time::timeout` per attempt. A timeout is classified separately from an I/O
  or parse error.
- `read_registration_dir`: list `<store>/workspaces/`; `NotFound` is an empty
  registry, any other error is a failure, never an empty registry. For each `*.json`:
  parse with `RegistrationData::from_file_bytes` (hash/path mismatch, unknown fields
  and newer versions fail naming the file), then probe
  `lockfile_path.parent()/refs` with `fs_metadata_async`:
  - `NotFound` → not live for this run, registration left on disk;
  - `Ok` or any other error → live (uncertainty keeps protection);
  - live: read that directory tolerantly.
- `read_reference_dir`: list the directory (`NotFound` → no references; any other
  error → failure). For each `*.json`, parse `RefSetData` **without**
  `check_kind`/`prepare_ref_set`/`reconcile_pins`. For every `kind → locator →
  selector → {pin}`:
  - pin that fails `is_safe_segment` → fail closed, naming the file;
  - kind with no registered driver → ignore (the store lists only registered kinds);
  - otherwise build `SourceSpec { locator, selector, connection:
    Connection::new(locator) }` and map through the pruner's own driver:
    `safe_slug(driver.slug(&spec))`. The selector is required because a custom
    driver's slug may depend on it; the connection is a placeholder because `slug`
    is specified over the address, not credentials.
- The caller's own `refs_dir()` is always read too, whether or not it is registered,
  so `--unused`/age from a workspace installed by an older omni never deletes its own
  checkouts.

Any error here is returned as `Error::custom(message)` naming the file and is a
refusal for the consulting flags.

### Filter and report

- `StorePruneFilter` gains `include_referenced: bool`, still `Copy`, default `false`
  (protective). `validate` adds:
  - `include_referenced` with `all` → reject;
  - `include_referenced` without `older_than` or `larger_than` → reject.
- `PruneReport` gains `skipped_referenced: Vec<StoreEntry>`.
- `consults_references()` is `!all && !include_referenced` in this step. `--all`
  never reads registrations.

### Prune loop

- Initial pass: when `consults_references()`, build the protected set once before
  deleting anything, for a dry run and a real run alike. A parse or persistent read
  error refuses the whole run. The dry run uses this set: an entry in it is reported
  in `skipped_referenced`, never in `removed`; the existing lease probe still
  reports `skipped_in_use` and wins on ordering (lease first, then reference).
- Real run: keep the current remote lock → exclusive try-lease order. **While still
  holding both**, re-scan registrations and the workspace's own refs and skip the
  entry if it is now referenced. A cached set is not enough: a registration written
  after the initial pass must protect the checkout.
  - Re-read failure: skip only that entry and report it in `failed` with the reason,
    never in `removed`. A timeout additionally stops per-entry re-reads for the rest
    of the run (`RegistryState::stopped`); every remaining entry is reported in
    `failed` with the one cause, so a hung mount cannot stall N × 5 s.
  - A referenced entry returns its guards without deleting; the exclusive lease is
    released, the tree stays.
- The in-lock re-read reads each registration and each of its reference files once
  per entry, not once per reference.
- Lock order is unchanged: install takes remote lock → shared lease → advisory lock;
  prune takes remote lock → try-lease → lock-free reads. Prune never takes the
  advisory lock and never waits on a lease.

### API

- `handle_remote_sources_prune` sets `include_referenced: true` whenever
  `older_than` or `larger_than` is set, and `false` for `--all`, so existing flags
  keep today's behavior. The core default is protective for direct callers.
- `RemoteSourcesPruneResponse` gains `#[serde(default)] skipped_referenced:
  Vec<StoreCheckoutView>`, mapped in `prune_response`.
- The existing "refusing to prune without a filter" message is unchanged in this
  step (step 4 names `--unused`).

### Failing-first tests

`crates/omni_remote_source/tests/store.rs` (two `Workspace::with_store(..)` managers on
one store root, different lockfiles):

1. B installs a checkout (materialize + `record_refs`/`update_ref_sets`, which
   registers B). A prunes by `older_than` with `include_referenced: false`: B's
   checkout survives and appears in `skipped_referenced`, in a dry run and a real
   run. Fails today (it is deleted).
2. Same setup with `include_referenced: true`: the checkout is deleted (unchanged
   behavior).
3. Same setup with `all`: the checkout is deleted and no registration is read.
4. B's `refs/` directory is removed after registering: not live, A deletes the
   checkout and the registration file remains.
5. B's `refs/` is unreadable (Unix, `permissions_are_enforced` skip pattern from
   `gc_leases.rs`): the consulting prune fails closed and deletes nothing.
6. B's references move to a new pin: the old pin is pruned, the new one survives.
7. Unknown kind in B's reference file: ignored, no error.
8. `fake_kind` driver whose slug depends on the selector: B registers a reference
   through it, A's driver maps it back, the checkout survives. This fails if the
   reader omits the selector.
9. Corrupt (or newer-version) registration: `older_than` fails naming the file;
   `all` still succeeds and deletes.
10. Unsafe pin in a foreign reference file: consulting prune fails; `all` succeeds.
11. A registration written between A's dry run and A's confirmed `only` pass: the
    confirmed pass re-reads, reports `skipped_referenced`, and leaves the checkout.
    Fails if the re-read trusts the initial set.
12. Own refs without a registration (older-omni workspace: delete A's registration
    file, keep `refs/`): A's prune still keeps its own checkout.
13. A lease still wins: a leased and referenced entry is reported `skipped_in_use`
    (or at least not removed) and never reads the registry first.

Unit tests in `default_impl.rs`: the extended validate matrix
(`include_referenced` × `all`/age/size/none). `omni_api` unit test: response mapping
carries `skipped_referenced` both ways.

Windows retry/delete-while-held cannot be tested here; noted in the PR.

### Checks and undo

`cargo test -p omni_remote_source`, `cargo test -p omni_api`, scoped clippy/fmt on
both. Undo: revert; registration files on disk are ignored by the old reader and
prune returns to lease-only retention.

## Slice C (step 4): `--unused` and the report

**One PR.** Medium; High risk (deletion selection). Ships after step 3.

### Change

- `StorePruneFilter.unused: bool` (default `false`), `Copy` retained. `has_criteria`
  includes it; `matches` treats it as "select every entry", leaving leases and
  references to decide. `consults_references()` becomes
  `!all && (unused || !include_referenced)`.
- `validate` adds: `unused` with `all`, `older_than` or `larger_than` → reject;
  `include_referenced` with `unused` → reject. Error messages name the flags.
- API: `RemoteSourcesPruneRequest.unused: bool` with `#[serde(default)]`; handler
  passes it through; the "refusing to prune without a filter" message names
  `--unused`.
- CLI: `--unused` with `conflicts_with_all = ["all", "older_than", "larger_than"]`
  and the help text from F08.7. Output lists `skipped_referenced` separately with a
  reason ("referenced by a registered workspace"), and the "nothing to prune" line
  mentions referenced checkouts alongside in-use and failed. The confirmed second
  pass already sends `only`; it now also re-checks references in the lock.
- Regenerate the command reference with the repo script; never hand-edit.

### Failing-first tests

- Core validate matrix: `unused` alone valid; with `all`, age or size invalid;
  `include_referenced` + `unused` invalid; `has_criteria` true.
- Integration: an unreferenced unleased checkout is removed by `unused`; a referenced
  one survives in `skipped_referenced`; a leased one is `skipped_in_use`; `only`
  still narrows.
- API: request without `unused` deserializes to `false`; response carries
  `skipped_referenced`.
- CLI parse: `--unused` conflicts; `--unused --yes` parses.
- e2e (`tests/omni-tests/src/remote-sources.e2e.spec.ts`, bun): install two git
  sources, remove one from config, install again (drops its reference), then
  `prune --unused --dry-run` lists only the unreferenced checkout and
  `prune --unused --yes` removes it while the referenced one stays and still lists.
  Runs with the existing `skipUnlessGitCliAvailable`.
- Release note: `--unused` is new; existing flags unchanged; older omni versions
  prune without reading registrations; workspaces register on the next reference
  write.

### Checks and undo

`cargo test -p omni_remote_source`, `cargo test -p omni_api`, `cargo test -p
omni_cli_core`, the e2e suite, scoped clippy/fmt, `bun run gen:refdocs`. Undo:
revert; the flag disappears and the core/report fields are additive.

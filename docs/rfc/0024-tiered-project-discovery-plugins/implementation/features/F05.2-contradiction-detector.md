# F05.2: Explicit-contradiction detector and `deciding_source` (part 1)

**Reader:** contributors wiring the planner (F05.2 part 2) and F06.3. **Status:** part 1
merged ([#130](https://github.com/omni-oss/omni/pull/130)). **Risk:** Medium: a pure detector that nothing calls, plus
one serialized field filled in. No planning outcome, cache key or eligibility changes. Slice
2 of [F05](F05-origin-aware-cache-tiers.md), built on
[F05.1](F05.1-origin-tagged-enablement.md).

## What changed

- `omni_task_executor::find_explicit_contradictions(&[ContradictionNode])` returns every
  pair where a task whose effective `cache.enabled: true` was **authored** (task or project
  tier) reaches an executable task whose `false` was also authored. Each
  `CacheContradiction` names both tasks and who decided each side, and its `Display` says so
  in one sentence.
- `CacheStatus::Disabled.deciding_source` is now filled from the task's origin
  (`task-explicit`, `project-explicit`, ...). It was always `None`. Tasks skipped as
  disabled or commandless still report `None`. `CacheEnabledSource::as_str` gives the
  kebab-case name and is tested against the serde form.

## Rules the detector applies

- Both sides authored, otherwise it is demotion (B04), never an error. Plugin, activation
  `defaults` and host-fallback sides never contradict, in either position.
- Only executable edges: a dependent is judged against what it reaches directly or through
  transparent nodes (no command, or disabled). Persistent tasks contradict nothing and stop
  the walk. A chain `a (authored true) -> b (fallback true, demoted) -> c (authored false)`
  is **not** a contradiction for `a`: `b` is not itself authored-false.
- Reported once per pair, in node order then dependency declaration order. Unknown
  dependencies and cycles among transparent nodes are tolerated.

## File provenance (F05.2 prerequisite)

The file-provenance slice is done ([#157](https://github.com/omni-oss/omni/pull/157)).
`LoadedContext::cache_enabled_file` returns the file
that set a task's effective authored value, including through project and task `extends`.
Settings without a file (including the host fallback) have no location. Provenance is
neither serialized nor included in cache keys.

The current `CacheLayer` field is a narrow first implementation. F07 records a
[configuration metadata redesign](F07-conflict-detection-and-provenance.md#follow-up-proposal-separate-authored-configuration-from-runtime-metadata)
to apply before adding more field-level provenance.

## Planner wiring (done)

`TaskExecutor::run` now plans the selection, runs the detector on the planned graph and fails
with `executor.cache_contradiction` before the plan is announced, so no task runs or reaches
cache lookup. The error lists each pair with both declaring files. Dry runs fail the same way,
and `ignore_dependencies` drops the edges. Tasks are classified from configuration only
(`classify_enabled`, shared with `TaskContext::is_enabled`); `enabled` expressions are never
evaluated. Re-audit of Omni's workspace with `omni cache eligibility`: 1,027 tasks, 63 with
expression conditions, 0 contradictions. Migration note: a workspace that sets
`cache.enabled: true` on a task that depends on an explicitly uncached task now fails to plan;
set the dependent uncached too, or enable the dependency's cache if reuse is safe. Revert the
wiring in `executor.rs` to restore demotion.

Tasks whose joined `project#task` name is shared by different (project, task) pairs (for
example `a#b` + `c` and `a` + `b#c`) cannot be told apart by the executor's name-keyed
results, so they are left out of the check (and of `omni cache eligibility`) rather than risk a wrong report.

Wiring tests (`omni_api` integration): the error carries both task names and declaring files;
no plan-ready or task-started event fires, no task runs and nothing is written to the cache
directory, for normal and dry runs; an unselected project's contradiction is not judged; a
definitely-false dependency (`"  FALSE "`, `"No"`) is transparent; an expression on the
dependent side still contradicts without being evaluated; `ignore_dependencies` drops the
edges. Task environments are evaluated when the context loads, before planning, as before.

  the latter are computed for the derived task, not inherited from the template.

### Decision: keep explicit-only errors

Keep [§8.3](../../008.02-execution-cache-semantic-identity.md#cache-enabled-tasks-and-uncached-dependencies):
error only when both sides are authored; otherwise demote. Rejected: an error for
every cached task that depends on an uncached one. In Omni's own workspace
(`6117b4c9`) that rule would reject 27 executable edges. All run from a task cached
only by the host default to an explicitly uncached task; the sampled ones depend on
`@omni-oss/site#prepare`, which must always run. Demotion also propagates up a chain without each dependent
opting out, and the plugin design makes inferred tasks uncached by default. A strict
opt-in mode may follow separately; it is not part of this slice.

### Decision: hard error

The planning error is a hard error, as the RFC specifies (decided with the maintainer; a
warning-first rollout was considered and declined). The compatibility audit and independent
review in the rollout plan below still apply.

### Planner wiring: rollout plan

**Scope and risk:** High. The new diagnostic changes which invocations fail
before execution. Leave cache keys, cache persistence, and the separate F07
metadata redesign unchanged. F09 owns the inspection surface.

1. **Audit real workspaces without running tasks.** Load definitions and use
   the executable dependency graph (not `with` edges). Report contradictions
   with every task whose `enabled` is not definitely false counted as
   executable, since the enforced rule counts them. A definitions-only result
   covers only the audited checkout.

   **Omni workspace baseline (`6117b4c9`):** 124 projects and 1,027
   executable-graph nodes, including 63 command-bearing nodes with expression
   conditions. A definitions-only probe loaded the real dependency graph
   without environment substitutions or task execution. The existing detector
   found no definite contradictions. A second walk treated each expression
   condition as either enabled or transparent, which is at least as strict as
   the rule (it also counted definitely-false strings as possibly enabled), and
   found no additional pairs: the rule would report zero
   contradictions here. No flattened task names collided in this workspace.
   This covers Omni's checked-out definitions only, not downstream workspaces.

2. **Classify tasks from configuration alone.** A task is skipped for this check
   only if it has no command or its `enabled` is definitely false: the boolean
   `false`, or an expression whose trimmed text, ignoring case, is a value
   `TaskContext::is_enabled` already treats as false without rendering (`false`,
   `no`, `n`, `0`). Implement the check by sharing that helper with `is_enabled`
   so the two cannot disagree. A persistent task is uncached whatever its setting.
   Every other task counts as executable, including one whose `enabled` is a
   template expression. Such conditions are still evaluated at execution time,
   exactly as today. The check does not evaluate conditions, load task
   environments or run command substitutions, so it runs before any task and
   needs no change to when environments load. This over-approximates: a config
   can be rejected although a runtime condition would have skipped the
   dependency. Both sides are explicitly authored, so the configuration does
   contradict itself; the fix is local (see step 4).

   **Later extension (not in this slice).** An expression that references only
   static inputs (`platform`, `meta`) and deterministic builtins could also count
   as predictable. That needs analysis of the template's variables and functions,
   not rendering with a restricted context: `is defined` and the `default`
   filter succeed on a missing variable, so a restricted render would misclassify
   runtime-dependent conditions. Omni's own expression conditions all depend on
   `env`, so it would not change the Omni audit. Adding it only removes false
   positives, so it can follow without a compatibility change.

   **Why conditions are not evaluated.** An executor experiment (not kept as a
   test) used a producer that writes a file and a consumer whose `enabled`
   condition reads it through `$(sh probe.sh)`. Evaluating the condition early
   disabled the consumer; normal batch evaluation enabled and ran it. Early
   evaluation would therefore change which tasks run, and memoizing it would
   skip a task that runs today. Tera time or random functions add a further
   source of difference.

3. **Fail before execution once a contradiction is found.** Use canonical
   task identity from the planned graph, not a joined `project#task` key that
   can collide. Report both task names and declaring files. Cover ignored
   dependencies, unrelated selections, a transparent intermediate task,
   persistent tasks, mixed origins, expression-enabled tasks on either side,
   definitely-false string conditions (including case and whitespace variants),
   and dry-run parity. A failing-plan fixture must show that no selected task
   runs, loads its environment or reaches cache lookup.
4. **Roll out after compatibility verification and independent review.** Record
   any affected workspace settings. If a dependency must stay uncached, set the
   dependent's cache policy to uncached too; only enable the dependency's cache
   if reusing its result is safe. Revert the planner wiring to restore demotion
   if needed; the file-provenance prerequisite can stay and there is no cache
   migration.

## Verification

- 9 detector tests: every authored pairing contradicts; every non-authored side in either
  position demotes; disabled dependents and enabled dependencies do not; transparent
  look-through; the edge-only rule; persistent stops the walk; ordering and one report per
  pair; unknown dependencies and cycles; the message content.
- Mutation checks bite: removing the dependent-authored check, the dependency-authored check,
  the persistent stop, or the visited set each fails a test (the last by hanging on the
  cycle test).
- `deciding_source` is covered in `cache_status` (value and origin together) and by the
  `as_str`/serde alignment test.
- The executor, configuration and CLI suites pass (313 tests); library and test-target
  clippy and formatting are clean.

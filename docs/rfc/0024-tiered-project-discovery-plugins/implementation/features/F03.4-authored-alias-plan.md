# F03.4: Authored task aliases and canonical selection

**Status:** built and merged (slices 1-4, one PR, [#175](https://github.com/omni-oss/omni/pull/175); see [Build result](#build-result)). The
revised plan passed fresh independent review in four rounds
([#167](https://github.com/omni-oss/omni/pull/167)) and the maintainer approved
building slices 1-4 together. Earlier revisions were blocked by independent
reviews (Claude Opus 5.5, Gemini 4 Neon, GPT-6.2-sol) and their findings are
folded in. The maintainer approved structured internal identity, a versioned
cache-key break, the shared authored-key grammar, preserved graph and report
wire formats, and direct-match filtering for inventory `--dir`/`--meta`. The
identity prerequisite is delivered by [slice 0](F03.4-slice-0-task-identity-plan.md).
**Kind:** Large.
**Risk:** High: this changes dependency and selector targets and adds guidance
to a destructive cache command.

## Assessment

- **Change:** authored decoding and schema, inheritance, task graph, live
  selection, project hashing, and cache-inventory diagnostics.
- **Unknowns:** prove that all live surfaces can share name resolution without
  changing raw storage selectors or collapsing names containing `#`. Test the
  boundary first with one alias and one mixed exact/pattern request.
- **Undo:** revert the feature as a unit. Aliases in authored files would need to
  be removed or changed back to canonical names before running an older binary.
  The new key version starts cold. No stored entries or cache metadata need
  migration; rollback uses the old keys, whose entries may still be present.
- **Effort and ownership:** several reviewable slices with one integration owner.
  Settle the lookup contract before splitting work. Require independent review
  and run combined tests across the graph, hash, cache, CLI and MCP callers.
  The identity prerequisite is planned in [slice 0](F03.4-slice-0-task-identity-plan.md). Reassess if it requires
  a persistent format change or plugin binding.

## Goal and worked example

Finish the handwritten part of [F03](F03-scoped-task-references.md) and the
alias-aware part of [F04](F04-exact-selectors-and-task-patterns.md) together.
Do not add automatic aliases, plugin scopes/bindings, or alias-derived cache
entries. The identity prerequisite changes the key inputs, not the entry
layout or metadata schema.

In project `web`, `compile: { alias: build-native }` names the same task as
`build-native`. Running either or both plans one canonical execution. A pattern
matching `compile` also selects it. A task list that uses `compile` in
`dependencies` or `with` gets a canonical edge; `extends: compile` inherits
the definition but creates its own task. `hash project` and cache eligibility
select the same canonical task and report canonical identity.

If `compile` was previously a real task, its old entries remain selectable
with `cache stats --project web --task compile` or the corresponding prune
request. If no stored `compile` matches and the live alias exists, suggest
`--project web --task build-native`; do not select or prune its entries. An
identical request's stored-name selection, and the paths approved by an
existing preview, must not broaden if the alias is retargeted. A new preview may
legitimately reflect changed stale eligibility when retargeting changes the
task graph or hashed configuration.

## Design and slices

### 0. Remove joined-name identity from internal lookups

**Approved direction; requires a separate implementation plan.** Use an
equality-checked key with separate project and task components through context
lookups, graph edges and execution results, and dependency and collector digest
maps. Audit the existing `TaskKey` and other intermediates for actual identity
semantics; a combined hash or delimiter-joined string is not a collision-free
identity. Use the structured pair for every internal decision; render a
`project#task` label only at boundaries, using the escaped, round-trippable
spelling of the shared reference grammar, and parse labels only at ingress.
Preserve persisted project and task names. Replace the joined-name digest contribution with a versioned,
length-framed encoding of the project and task components. Use the new key construction
consistently across execution, dry run, hash commands and stale inventory.
This intentionally invalidates old keys: ship a release note, do not fall back
to or promote legacy hits, and leave old entries to normal pruning. Coordinate
the key cutover with F06.3 to avoid two cold starts if the two can ship together;
do not pull the rest of F06.3 into this prerequisite.

**Checks:** `(a#b, c)` and `(a, b#c)` keep distinct context, edges, results and
digest lookups in the same workspace and produce distinct identity inputs.
Pin unchanged stored names and metadata, old/new digest fixtures, and parity
across lookup, write, dry run, hash and stale inventory. Land this prerequisite
before activating aliases; it can be reverted independently before then. Stop and
re-plan if storage or transport cannot preserve those compatibility boundaries.

### 1. Produce a canonical alias index from surviving declarations

**Depends on 0. Starting points:** `omni_configurations/src/layer.rs` (`TaskLayer::Alias`,
`merge_named`, `finalize_composed`), `task_extension.rs`, and the project schema
entry point in `omni_api/src/operations/config_schema.rs`.

Use an authored schema generated from `ProjectLayer` (add schema support for
that loader type), separate from the resolved `ProjectConfiguration` schema.
Wire the authored schema into `handle_config_schema(Project)` and the existing
schema publication path. Compare generated schema acceptance with the actual
loader, including `merge` and `replace` envelopes; preserve existing accepted
non-alias forms and do not hand-edit published artifacts.

The authored schema must follow the loader, not the resolved type. Pin these
differences: the loader requires an operator (`merge` or `replace`) to be the
sole key of the `tasks` object and gives an object-valued operator precedence,
so model the `tasks` collection as an operator-aware schema override rather than
the plain untagged union. A task or alias literally named `merge` or `replace`
is declared inside an explicit outer envelope, for example
`tasks: { merge: { replace: { alias: build } } }`. Reject a mixed operator envelope and malformed alias or task shapes in the
schema and the loader alike. JSON Schema cannot express that two raw keys
normalize to the same task (for example `lint:fix` and `lint\:fix`), so the
loader alone enforces normalized-key duplicates; exclude them from schema
parity assertions.
Switching `SchemaKind::Project` to `ProjectLayer` intentionally relaxes `name`
from required to optional (needed for `base` and extended layers); call that out
in the migration note. Hide internal layer types from the generated schema
(`TaskLayer::Composed` and the loader-only cache fields need `schemars(skip)`),
and give `TaskAliasLayer` `deny_unknown_fields` plus `JsonSchema` so a mixed
alias and task object is rejected by both. `base: true` projects still decode
alias entries strictly and normalize their keys, but skip surviving-alias
target existence and runnability validation until composed into a concrete
project.

Decode an alias as a strict `{ alias: <string> }` alternative. Reject mixed
alias/task fields during decoding even if composition would later remove them.
Keep ordered normal/alias replacements atomic. After the composed task map is
known, resolve surviving alias chains using the same-project alias-target
surface of `omni_types::TaskReference`. Use escaped names for literal
delimiters; reject plugin-qualified targets in this standalone slice rather
than reinterpreting them as literal task names. Normalize declaration keys
before merging their entries and preserve each declaration's source. Detect
two spellings of the same canonical key within a layer as a duplicate; across
layers, apply the existing ordered merge/replace rules to that canonical key.
Decode surviving `extends` operands at extension lookup, not by rewriting
stored declarations. Use the shared declaration/extends surface grammar and
document how to escape legacy literal `::`, `#`, leading `^`, and backslashes.
Report unsupported qualification with the original spelling and a literal
escape suggestion where applicable. This is an intentional pre-v1 change:
existing keys containing reserved syntax need escaping, as do references to
them. Include a migration note with examples of both declarations and uses.

```rust
// Illustrative: this index belongs to one resolved project, not the cache.
struct TaskAliases {
    canonical_by_alias: Map<TaskName, TaskName>,
}
```

Reject cycles and missing targets, use canonical targets when resolving
`extends`, and require surviving aliases to target runnable definitions after
inheritance. A base template may still be extended directly; it cannot be a
runnable alias target. Keep aliases outside the executable task map. Use
separate project and task components in new indexes; don't join them with `#`.
Ensure the authored schema accepts exactly the alias shapes the loader accepts;
don't expose the internal index by serializing the resolved configuration.

**Checks:** alias-only decode/schema parity; mixed objects rejected even if
replaced; discarded aliases skip target validation; normal/alias replacements;
chains, alias-to-alias replacement, alias cycles, missing/base targets,
commandless runnable targets, escaped names and inheritance self-cycles made
visible by alias canonicalization. Include operator-named aliases and tasks inside an explicit outer envelope,
malformed mixed entries even when discarded, and, for the loader only, normalized-key duplicates in each envelope. Rollback removes the decoder and index together, and republishes
`project.json` from the rolled-back binary version through the existing schema
publication workflow so editors stop accepting `alias`.

### 2. Resolve executable references before creating task edges

**Depends on 1.** Thread the resolved index through the project catalog and
lookups used by `project_data_extractor.rs` and
`omni_core/src/task_execution_graph.rs`. After composition and task inheritance,
resolve surviving `dependencies` and `with` references. The root lookup must
return a canonical `(project, task)` pair rather than returning a project and
leaving the input task unchanged. The graph resolves own and named-project
operands through the target project's alias index before edge insertion. For
`^name`, resolve separately against each upstream project; a project with no
such public name adds no edge at that project, and the walk continues into that branch's predecessors, stopping at the first match, as `add_upstream` does today; an existing alias with an invalid target remains an
error. Pass already-decoded host and generated shorthand operands as raw task
components, not reference strings. Lower root references to canonical pairs
after inheritance and before graph insertion without re-decoding typed operands
or losing their provenance, and carry an alias-origin marker from lowering to
edge insertion so the graph can tell an alias reference from an explicit
canonical one.

Duplicate rule, per edge kind and independent of declaration order: explicit
canonical references keep their existing slots and multiplicity; an alias
reference whose canonical target already has an explicit slot collapses into it;
alias references to the same target (including repeated ones) with no explicit
slot collapse to the first occurrence. If general deduplication is needed, plan
its cache-key impact separately. The existing `has_connected_node` check uses
`find_edge`, which returns a single edge, so a task with both a dependency and a
`with` edge to the same target could in principle miss an existing sibling edge. Fix it to
test every connecting edge of the requested kind
(`edges_connecting(..).any(|e| *e.weight() == edge_type)`) and add a regression test before relying on it for deduplication. Upstream
references (`^x`) that resolve to the same target, directly or through an alias,
count as explicit occurrences for slot purposes. Do not change how explicit and
upstream references combine when no alias is involved: pin both declaration
orders as a baseline (today `^x` collapses into an explicit `x` edge only when
the explicit one comes first). The `has_connected_node` fix is behavior-preserving for
graphs built from configuration (measured against c7aa81fc: every pinned
project and workspace digest is identical before and after), so no digest
baseline breaks and the release note claims none. Keep the graph's normal dependency
and sibling cycle checks.

**Checks:** two upstream projects can bind `compile` differently; a third can
omit it. Cover both edge kinds, root references, replaced references, an
upstream alias plus an explicit canonical edge in both declaration orders,
and a mixed dependency/`with` contradiction that only appears after lowering.
Add a dependency and a `with` edge to the same target, an intermediate project
with no match above a deeper alias match, an intermediate match that stops the
walk, a diamond, and two explicit canonical slots plus one alias slot in both
orders for `dependencies` and `with`. Pin an explicit-only duplicate-dependency
hash as a baseline. Rollback restores
literal lookup and requires reverting the authored alias feature with it.

### 3. Share public-name selection across live callers

**Depends on 1–2.** Produce a shared selection result with separate structured
sets for directly matched canonical tasks and the expanded plan. Use the
direct set for `ProjectHasher`'s final aggregation; dependency digests can
contribute through the graph, but dependency-only tasks must not become direct
aggregate inputs. Remove the hasher's second match against raw digest names.
Use the same per-project resolver in exact validation and `DefaultTaskFilter`.
Once this slice activates, a displayed label (the shared grammar's escaped
spelling) is a valid exact selector. Parse live exact selector input once at
ingress: CLI `commands/run.rs` and the API handlers in `operations/task.rs` and
`operations/hash.rs`, which serve MCP, the hash frontends and `cache
eligibility`. Make F09 live-selector parsing and CLI and MCP parity
unconditional requirements of this slice. Parse with the shared reference
grammar: project-qualified names scope to one project; wildcard characters in
exact names are literal. Do not reparse
internally generated raw names (for example `Call::Command`'s synthetic task
name) or feed patterns through the reference parser. Define the type boundary
explicitly: add a parsed exact-selector variant (optional project qualifier plus
raw task) beside the raw `TaskSelector::Exact(String)` that inventory and
internal callers keep, and have planning return a selection result with
`direct` (structured canonical pairs) and `plan` (the expanded batches).
`hash project <name>` accepts a project-qualified selector only when its
qualifier equals `<name>` and rejects any other project with a clear error;
an unqualified selector resolves within `<name>`. `--with-dependents` keeps
today's behavior: the seed is the direct match set, and the dependents search
applies only the task-name predicate (alias or canonical, resolved per project),
so a project qualifier scopes the seed and not the dependents traversal. Pin
that with a cross-project dependent fixture.
Patterns match canonically rendered public names. Match the union of exact and
pattern selectors, canonicalize, then deduplicate before execution or hashing.
Check each exact selector within project/directory scope before meta and
affected-file narrowing. Filters and task settings always belong to the
canonical task. Never retry a missing exact selector as a glob.

Before enabling live resolution, add a separate **raw canonical-name** mode
for cache inventory's shared planner callers in `omni_cache`'s `hybrid.rs`.
`allow_missing_exact` alone is not sufficient. Raw mode never parses selectors,
expands aliases or matches rendered public names; preserve exact/glob union,
no-filter defaults, and existing directory/meta behavior for historical
entries. With `--dir` or `--meta`, inventory uses **direct canonical matches**
(decision D2): apply the same task predicate (project, task selector, directory,
meta) to current definitions without expanding to dependencies, then keep stored
entries whose `(project, raw task)` pair is in that set. Removed tasks stay
unmatchable under `--dir` and `--meta`, as today. This is an intentional
behavior change (dependency-only tasks are no longer selected) and needs a
release note; stale hashing keeps the full dependency graph. Use it for stale observation in each worktree and keep orphan
observations keyed only to executable definitions. This isolation ships with
the first alias release, not with the optional hint.

**Checks:** CLI and MCP agreement; alias plus canonical or pattern selects
once; one missing exact name is not hidden by a successful glob; literal
wildcards, backslashes, escaped `#` and `::`; qualified selection; metadata and
affected-file parity; selected alias and canonical name give the same digest
for the same checkout. This does not promise that editing the config file
leaves its existing file-input digest unchanged. Include current run cache
status and F09 CLI and MCP parity in the checks (F09 is on `main`).
Include a same-project closure-only task that is excluded from the final hash
fold, so a cross-project-only test cannot pass by accident. Revert this with
slices 1–2 so no authored alias ships without live selection.

### 4. Add an advisory hint to canonical-only cache inventory

**Depends on 1 and the existing F04 cache selector split.** Preserve the current
matching semantics for `cache stats`, `cache prune`, and their MCP tools:
exact selectors and patterns match stored canonical names. Keep inventory
planning distinct from live alias-aware selection, including when prune builds
plans for directory/meta filters, staleness, or peer worktrees.

For each exact selector with no valid stored `(project, raw task)` pair in its
project scope, look for a live alias and suggest the canonical name and project.
A stored hit in any scoped project suppresses hints for that selector, not for
other exact selectors in the request. Determine a miss on the existing cache
views before directory/meta, age, size, stale/orphan and approval predicates;
an empty or nonempty final result is not evidence of a name miss. Patterns get
no alias expansion or hint.

Use a best-effort definitions-only load of the invoking workspace, never a peer
workspace or a new normal load. Drop the hint on load failure without changing
the inventory operation's result. Do not trigger commands or environment
substitutions to obtain it. Carry hints separately from entries as additive response metadata.
`handle_cache_stats` returns a response with the existing stats plus
`hints: [{ selector, project, alias, canonical }]` (a pre-v1 Rust return-type change; note it, and `OmniApi::cache_stats` changes
with it). Keep the JSON additive: flatten the existing stats and add `hints` with
`#[serde(default, skip_serializing_if = "Vec::is_empty")]`, and the same on `CachePruneResponse`. The MCP
`cache_stats` and `cache_prune` results gain an optional `alias_hints` array,
omitted when empty. Display them even when CLI prune has an empty preview, and preserve
them in MCP's projected response. No hint enters inventory matching, the
approved path set, or confirmation.

**Checks:** historical canonical names remain selectable; alias-only exact
miss yields a hint but no changes to selected entries; retargeting changes only
the hint; predicates and preview/confirmation never fall through; patterns stay
canonical-only. Compare actual prune results with and without alias hints on a
shared-cache fixture at fixed workspace state, including approved paths.
Separately test stale recomputation after retargeting, mixed selectors, exact
hits in only one project, and no substitutions attributable to the hint.
Test the three existing deletion paths separately for each: ordinary CLI prune
acts on the previewed entries, stale and orphan CLI prune recompute and
intersect with the approved paths, and MCP prune is a direct API call. Rollback
removes the hint without changing any selector.

## Build gate

**Authored syntax decision:** use the RFC's shared declaration-key grammar in
this release, with a pre-v1 escaping migration note. Alias and live selector
operands must have one unambiguous mapping to canonical keys. Do not silently
reinterpret an unsupported plugin-qualified name as an existing literal task.

**Decisions recorded.** D1: preserve the existing graph, result and report wire
formats and add a typed execution boundary (see slice 0). D2: `--dir` and
`--meta` inventory filtering uses direct canonical matches and keeps full-graph
stale hashing (slice 3).

The first implementation proof after approval is one thin fixture through
authored decode → canonical graph → run/hash → raw inventory, owned by the
integration implementer. Review that proof before splitting the larger work.
Rehearse rollback on a checkout with authored aliases, scripts that use new
escaping, and historical cache entries; restore scripts/config for the old
binary and show the old stored names still select only their entries.

Review the revised contract and approve before building. Use
[RFC §7.4](../../007.03-task-scoping-aliases-and-selectors.md) as the semantics
reference and preserve current behavior for workspaces with no aliases, except
the documented move to the shared grammar for live exact references. Include
the required escaping examples in user docs and keep authored aliases, graph
wiring, and live selectors in the same user-visible change. The cache hint
can land separately after that change.

## Build result

Slices 1-4 landed together on top of slice 0, in plan order, with the thin proof
fixture first (`tests/omni-tests/src/task-aliases.e2e.spec.ts`: one alias and
one mixed exact/pattern request through run, hash, cache eligibility and MCP).

- **Slice 1.** `TaskLayer::Alias` decodes strictly (`{ alias }` only; mixed
  objects fail while decoding). Declaration keys are normalized with the shared
  grammar when a layer is read, with duplicate detection per envelope.
  `finalize_composed` removes aliases, resolves chains over the composed task
  names, validates targets after inheritance, and returns `TaskAliases` on
  `FinalizedProject`. `extends` operands are decoded at lookup and resolved
  through the index. `SchemaKind::Project` now generates from `ProjectLayer`
  (`tasks` uses an operator-aware schema override); an e2e spec compares schema
  and loader acceptance with `@cfworker/json-schema`.
- **Slice 2.** `omni_core::Project` carries the alias index (not serialized).
  The graph resolves own, named-project and upstream operands through each target
  project's index before inserting edges, with the duplicate rules above and the
  `has_connected_node` fix. Root references validate against tasks and aliases
  and are lowered with the alias name; the graph resolves them.
- **Slice 3.** `TaskSelector::Reference` and `parse_exact` at the four ingress
  points; `ExecutionSelection { direct, plan }`; `DefaultTaskFilter` resolves
  references and matches patterns against canonical names and aliases; project
  hashing folds only the direct set; cache inventory plans in raw
  canonical-name mode with direct matches for `--dir`/`--meta`.
- **Slice 4.** `CacheAliasHint` on `CacheStatsResponse` and `CachePruneResponse`
  (`hints`), `alias_hints` on the MCP results, and a CLI hint line.

Deviations and notes:

- Root references (`ProjectRoot`) are validated against tasks and aliases in the
  extractor but lowered with the written name; the graph does the final
  canonicalization, so the alias marker is inferred from the target project's
  index and no wire type changed.
- Patterns match the raw canonical name and the raw alias names. The plan's
  "canonically rendered public names" would make `\#` in a pattern a glob escape
  and an escape at once, so rendering was not applied to patterns.
- Alias hints read the invoking workspace's already loaded definitions instead of
  a separate best-effort definitions-only load (maintainer accepted: cache stats
  and prune already require the loaded context). Prune computes them from the
  stored names before deleting, so an entry removed by the same prune still
  suppresses its own selector's hint.
- `has_connected_node` fix: measured against c7aa81fc, every pinned project and
  workspace digest is identical before and after (see
  `tests/omni-tests/src/graph-edge-baseline.e2e.spec.ts`). The fix is
  behavior-preserving for graphs built from configuration.
- Own-project alias references in `dependencies`, `with` and `siblings` resolve
  through the alias index in the extracted-data validator as well as the graph.
- A duplicate `alias` key inside one alias object is not rejected: like any
  duplicate key in a configuration object, the last one wins. A key such as
  `a:b` is not special: it keeps decoding as the task named `a:b`.
- Empty and NUL declaration keys pass through key normalization unchanged so the
  existing `workspace.invalid_task_name` diagnostic still names the project.
- Release note: `apps/site/content/docs/guides/task-aliases-and-selectors.mdx`.

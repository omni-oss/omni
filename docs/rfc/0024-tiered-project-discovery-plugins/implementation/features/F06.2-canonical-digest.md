# F06.2: Canonical effective-task digest

**Reader:** contributors implementing F06.3 (plumbing and parity) and anyone changing the
encoding. **Status:** merged ([#114](https://github.com/omni-oss/omni/pull/114)), unused until F06.3; **Risk:** High (cache keys).
Implements slice 2 of [F06](F06-effective-semantic-digest.md) against the inventory in
[F06.1](F06.1-effective-field-audit.md).

## What this is, and is not

A pure function: `EffectiveTaskConfig::digest()` in `omni_collector::effective_task`. It
turns a typed projection of a finalized task's execution semantics into a 32-byte digest
through a versioned canonical encoding. **It is not wired into any cache key.** No
collector, executor, store or remote path calls it, so existing keys are unchanged and
nothing is invalidated by this change. F06.3 does the plumbing, and that is where keys
change once.

## Assessment

- **Kind / risk:** Medium work, High risk (cache-key domain override in `AGENTS.md`), though
  nothing consumes it yet.
- **Unknowns:** whether the encoding can be both canonical and collision-free, and what the
  digest should cover versus leave to the invocation. The first is settled by tests, the
  second by the decisions below.
- **Undo:** revert; the module is additive and unused.
- **Out of scope:** plumbing (F06.3), the workspace hasher's aggregation, the benchmark
  (slice 5).

## The encoding

The encoding is the contract. The digest is `DefaultHasher` (omni's BLAKE3) over exactly
those bytes. The layout is documented on the module and pinned by two kinds of test:

- a hand-written, independent oracle for the default configuration (so the encoder is
  checked against the spec rather than itself), and
- a golden vector for a fully populated configuration, as both the encoding bytes and the
  digest. If either changes, existing keys would silently change, so a change is only
  legitimate with a new `VERSION` (`effective-task-config/v1`).

Properties: every value is length- or tag-framed (no boundary-shift collisions); every
option and enum carries an explicit presence or variant byte; each field has an id; maps
are key-sorted; unordered sets are encoded, sorted and deduplicated; ordered lists (command
arguments and operands) keep their order; floats are canonicalized (`-0.0` and NaNs);
integers and floats, and strings and integers, are distinct types.

## Decisions

| Question (from F06.1)                                                                                        | Decision                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Interpretation mode                                                                                          | Encoded: shell, argv, and each operand's mode (literal, expression, interpolated with its bindings). A literal and an equal-text expression differ.                                                                                                                 |
| Retry                                                                                                        | The _resolved_ `RetryPolicy`, so an explicit value equal to a default digests the same as omitting it. Exhaustive matches mean a new `Backoff` or `Jitter` variant fails to compile until the encoding handles it.                                                  |
| Metadata                                                                                                     | Included, conservatively: expressions can read it and narrowing is unproven.                                                                                                                                                                                        |
| Enabled                                                                                                      | Boolean and expression are different definitions. Task enablement is not cache enablement.                                                                                                                                                                          |
| Log capture (F06.1 open item)                                                                                | **Included** as an artifact-policy field. An entry stored without logs cannot replay them, so a task that later asks for logs must miss. This is the capture policy, not log display, which is excluded.                                                            |
| Path-rule sets, dependencies, siblings                                                                       | Treated as unordered sets: order and repetition do not reach the digest, but the root and the include/exclude side do.                                                                                                                                              |
| Cache enablement, description, `base`/`extends`, display policy, redaction, results                          | No field exists, so they cannot reach the digest.                                                                                                                                                                                                                   |
| Platform, environment, merged invocation arguments, retry overrides, path context                            | **Carried forward to F06.3, deliberately.** They belong to the invocation, not the finalized definition. Adding platform to this per-task digest would also stop unrelated tasks sharing a remote cache across operating systems, which needs an explicit decision. |
| Workspace hasher aggregation, resolved-dependency timing, nondeterministic expressions (`now`, `get_random`) | Carried forward; not decided here, and not claimed safe.                                                                                                                                                                                                            |

## Verification

- 17 behavior tests in `crates/omni_collector/tests/effective_task.rs`, plus the existing
  collector tests (53 in the crate): the default-layout oracle; the golden vector; digest
  equals the hasher over the encoding; every included field changes the digest; explicit
  defaults equal omitted ones; boolean vs expression; shell/argv/literal/expression with the
  same text never collide; interpolated binding values and names; main vs retry command;
  list order and boundary-shift cases; presence and type distinctions; the same content in
  different fields; map-order invariance (including nested JSON); set order and repetition,
  root and include/exclude sides; float and JSON number canonicalization; the version tag.
- The tests bite: removing length framing fails four of them, and removing set
  canonicalization fails the set test.
- Not covered here: benchmarks (F06 slice 5), any integration with the collector or cache,
  and cross-platform agreement of the encoding. It uses only fixed-width little-endian
  integers and UTF-8, so it should not vary, but that is argued, not tested on other targets.
- An independent BLAKE3 implementation was not available, so the digest value rests on the
  hasher test rather than a second implementation.

## For F06.3

including with `cache.key.defaults: false`. Decide the carried-forward items above, and run

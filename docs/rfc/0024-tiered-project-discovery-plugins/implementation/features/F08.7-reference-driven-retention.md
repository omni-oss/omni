# F08.7: Reference-driven retention (D3)

For source-manager contributors. Resolves decision D3 in
[F08.1](F08.1-lease-gc-reference-protocol.md): should `prune_store` protect
checkouts that workspaces reference? Builds on leases ([F08.3](F08.3-gc-honors-leases.md))
and the reference API ([F08.4](F08.4-atomic-reference-api.md)).
**Status:** plan, revised after two independent reviews (concurrency, semantics). Not started. Filter validation, the first step, is merged ([PR #193](https://github.com/omni-oss/omni/pull/193)).

## Assessment

- **Kind:** Large. It adds a store file format and lifecycle, changes the install lease
  lifetime and the contributor trait, changes `update_ref_sets`, `reconcile_pins` and
  prune, and touches the CLI, API and docs. It reverses the RFC 0027 §4.3 and F08.1 D3
  position, so it needs a maintainer decision.
- **Risk:** High (deletion and retention in a shared store, a persistent format,
  concurrency). Independent review is required on every step.
- **Undo:** each step is revertable. After step 3 ships, reverting leaves registration
  files on disk that older readers ignore; that is harmless. A wrongly pruned checkout is
  refetched (network, and offline use breaks until re-install). Over-retention wastes disk
  and gives no signal.
- **Not decided here:** automatic prune, expiring registrations of workspaces that still
  exist.

## Problem

Prune reads no references, and references are per workspace (`<workspace>/.omni/sources/refs/*.json`)
while the store is shared per user. An idle checkout, one that no process holds a lease
on, is deleted by any prune, even when a workspace installed it for offline use. Making
prune read only the pruning workspace's references would protect that workspace's
checkouts and delete every other workspace's (the failure RFC 0027 §3 recorded for
`retain()`).

## Decisions taken

- **Registrations are pointers.** Each workspace registers itself in the store with a
  small file that points at its reference directory. Prune reads that workspace's
  `refs/*.json` live. The registration holds no checkout list, so it cannot go stale and
  there is no second copy of the references to keep in step.
- **`--all` is unchanged.** It selects every checkout (leased ones are still skipped).
  A new `--unused` selects only unused checkouts. No existing script changes meaning.
- **Age and size filters protect referenced checkouts by default.** The `.used` marker
  only changes on materialize, so an installed-but-idle checkout always looks old and
  `--older-than` would otherwise delete exactly what registrations keep. An override,
  `--include-referenced`, widens age and size filters. This is a visible behavior change
  for existing `--older-than` and `--larger-than` users (see Release note).
- **Filter rules first.** Combinations are validated in the core (#193) in
  `StorePruneFilter::validate`; the new flags extend that function.
- **No automatic expiry** and **prune never deletes a registration.** See "Registration
  lifecycle". A `workspaces` list/forget command is a separate follow-up.
- **Store `VERSION`:** the layout change is additive (`workspaces/`), so the plan assumes
  no bump, but protection only works if every pruner understands registrations and an
  older omni deletes anything unleased. That ties this to F08.1 D1, which is open and
  belongs to the release owner. Deciding D1 is a release gate for step 3 (see Open
  questions).

## Definition: unused

A checkout `(kind, slug, pin)` is **unused** when, at the moment prune evaluates it, all
three hold:

1. **No lease.** No process holds a `SourceLease` on it (prune's non-blocking exclusive
   lock succeeds). Otherwise it is in use (`skipped_in_use`).
2. **Not referenced.** No live registration's reference sets name that exact
   `(kind, slug, pin)`. Otherwise it is referenced (`skipped_referenced`).
3. **Registry readable.** For flags that consult registrations, every registration and
   the reference sets it points at could be read. See "Failure handling" for what
   happens otherwise.

A registration is **live** when its reference directory exists, or when checking it
fails with anything other than `NotFound` (uncertainty keeps protection for that run).
A `NotFound` registration is **not live for this run** and is left on disk.

Unused does **not** mean old (the `.used` marker is only used by `--older-than`), does not
cover other users, and does not cover workspaces that have not registered. A moved
workspace is not live until it writes references again. It is a snapshot, not a guarantee
nothing needs the checkout later; a deleted checkout is refetched.

## Design

### Registration file

`<store>/workspaces/<hash(normalized lockfile path)>.json`, written with
`atomic_file::write_batch`.

- `version` (`1.0.0`, `deny_unknown_fields`), `lockfile_path` (the normalized absolute
  path, kept to detect a hash collision), `last_seen`.
- **Keyed on the lockfile path, not the workspace path.** The reference directory is
  `lockfile_path.parent()/refs`, which is what actually keeps checkouts needed, and the
  manager already holds `lockfile_path`, so no new config field is needed. A workspace
  directory that still exists but whose `.omni/sources` was wiped is correctly not live.
- **Normalization:** canonicalize; on Windows strip the `\\?\` verbatim prefix; case-fold
  the hash input on case-insensitive filesystems. A second workspace at the same path
  overwrites the first, which is correct.
- Written by every `update_ref_sets` (install and the lazy generator and tool runs go
  through it) and `reconcile_pins`. `persist_pins` and `lock()` touch only the lockfile
  and do not register. A workspace that never wrote references is unregistered and
  unprotected.
- An empty release writes the registration; it never deletes it.

### Prune

1. Validate the filter.
2. Resolve the protected set only for flags that need it (`--unused`, `--older-than`,
   `--larger-than` without `--include-referenced`). `--all` and `--include-referenced`
   do not read registrations.
3. For each selected entry: take the remote lock, then the lease with try-lock (unchanged),
   then **re-read the registrations and their reference sets while still holding both**
   and skip the entry if it is now referenced. A cached set is not enough: with step 1
   an install either holds the lease (try-lock fails) or has finished writing its
   references (the re-read sees them).
4. The set maps `(kind, locator, pin)` in each reference file to `(kind, slug, pin)` with
   the pruner's own drivers (`safe_slug(driver.slug(spec))`). A reference to a kind the
   pruner has no driver for can never match an entry that `store_entries` lists, so it is
   ignored.
5. Report protected entries as `skipped_referenced`. The CLI's confirmed second pass
   (`only`) re-checks the protected set instead of trusting the dry run.

### Registration lifecycle

- **Prune never deletes a registration.** A `NotFound` reference directory may only mean
  the path is not visible from where prune runs (a bind-mounted store inside a container,
  WSL or a CI runner), and deleting would permanently strip the host's protection. It is
  treated as not live for that run only.
- Registrations accumulate for removed worktrees and ephemeral CI workspaces. They are
  tiny. The `workspaces` forget follow-up reclaims them by path or by `last_seen`; until
  it exists they stay. A store shared across mount namespaces cannot protect checkouts
  from a pruner that cannot see the workspace; this limit is documented.
- A workspace that uses different stores registers in each; a reference to a checkout
  that is not in a given store is harmless.

### Failure handling

- A corrupt or newer-version registration or reference file makes the consulting flags
  (`--unused`, `--older-than`, `--larger-than`) refuse to run and name the file.
  `--all` and `--include-referenced` still work, so the escape hatch never depends on
  the registry being healthy.
- A transient read failure (a concurrent replace, antivirus or sharing error on Windows)
  is retried briefly. `NotFound` of a registration file between listing and reading is
  retried too; only a persistent error fails closed. This is unverified on Windows (see
  Open questions).

### Lock order

The advisory lock is short and never held while waiting on a remote lock or lease.
Prune order stays remote lock, then lease. Registration files are replaced atomically,
so reading them needs no lock. Prune takes no registration lock because it never writes
one.

## Behavior

| Flag                            | Selects                        | Referenced checkouts |
| ------------------------------- | ------------------------------ | -------------------- |
| `--all`                         | Every checkout                 | Included (unchanged) |
| `--unused`                      | Every unused checkout          | Protected            |
| `--older-than`, `--larger-than` | Checkouts matching age or size | Protected by default |
| `--include-referenced`          | Widens age and size filters    | Included             |

Leased checkouts are always skipped and reported as `skipped_in_use`.

Combination rules, enforced in `StorePruneFilter::validate` so the CLI and API share them:

| Combination                                                      | Result                                                             |
| ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| `--all` with `--unused`                                          | Reject (`--all` already includes everything)                       |
| `--all` with `--older-than` or `--larger-than`                   | Reject (already enforced)                                          |
| `--unused` with `--older-than` or `--larger-than`                | Reject (redundant: age and size already skip referenced checkouts) |
| `--include-referenced` with `--unused` or `--all`                | Reject (contradictory or redundant)                                |
| `--include-referenced` without `--older-than` or `--larger-than` | Reject (nothing to widen); the clap message names those flags      |
| Zero `--older-than` or `--larger-than`                           | Reject (already enforced)                                          |

The response gains `skipped_referenced` (`#[serde(default)]` on every new request and
response field to stay wire-compatible), and the dry run lists referenced checkouts
separately so the user sees what `--include-referenced` would add. The CLI help for
`--unused` reads: "Select checkouts that no running command holds and no registered
workspace references. Workspaces register when they write references (install, or a
generator or tool run)." The `--older-than` help says it skips referenced checkouts.
There is no MCP prune tool, so no MCP change.

`--unused` and the new behavior of the age and size filters ship together (step 4), after
prune reads registrations. Before then they would mislead.

### Release note

- `--older-than` and `--larger-than` now skip checkouts referenced by a registered
  workspace. Scripts that relied on them to reclaim a workspace's checkouts stop doing so
  once that workspace has run install, with no signal. Use `--include-referenced` to
  restore the old selection.
- `--all` is unchanged. `--unused` is new.
- Older omni versions prune without reading registrations. Workspaces register when they
  next run install (or a generator or tool run that writes references).

## Install lease scope (step 1, reworked after review)

Install is unprotected in a wider window than first thought:

- Generator and tool contributors take **no lease at all** (`materialize_flat_remote`
  calls the unleased `materialize`). Pack nodes then materialize through that same path.
- Projection and pack-expansion leases are dropped inside `contribute`.
- `RemoteSourceContributor::contribute` returns only `Vec<RemoteSourceRef>`, so leases
  cannot be returned. Contributors also run one after another with their results
  unleased.
- The window spans network fetches and ends only after `update_ref_sets` and
  `reconcile_pins` (`omni_api/.../remote_source.rs`, around lines 346-347).

The fix:

- `run_contributors` owns one `LeaseSet` for the whole install and passes it to every
  contributor (a trait change, for example a `&LeaseSet` parameter on `contribute`;
  grep for other implementors first).
- Every contributor materializes with `materialize_into`, including the flat generator
  and tool paths.
- The set is dropped explicitly only after `reconcile_pins` returns.
- Cost: one open file descriptor per resolved checkout until the install ends.
- Lazy generator and tool runs already return their `LeaseSet` after `update_refs`, so
  they are fine.

## Steps

1. **Install owns one `LeaseSet` until references are written.** Trait change and the
   flat paths. Tests: a pruner running continuously against an install never removes a
   checkout the install resolved, including a generator-only install, which is unleased
   today; the test fails without the change.
2. **Registration format and write path.** `workspaces/<hash>.json` written from
   `update_ref_sets` and `reconcile_pins`. Tests: written on first write, idempotent,
   survives an empty release, hash collision detected, normalization (Windows prefix,
   case), corrupt existing file, concurrent updates, failure injection leaves a valid file.
3. **Prune engine reads registrations and references.** Protected set, in-lock re-read,
   drivers-based slug mapping, failure handling, confirmed-pass recheck. Release gate:
   the D1 decision. Tests: two workspaces on one store (A's prune keeps B's checkout;
   today it deletes it), missing reference directory (not live, registration kept),
   unreadable directory (live), moved pin, unknown kind, corrupt registration refuses
   the consulting flags but not `--all`, a registration written between the dry run and
   the confirmed pass.
4. **API and CLI surface.** `--unused`, `--include-referenced`, `skipped_referenced`,
   updated CLI messages (today they say only "in use or failed"), regenerated command
   reference (never hand-edited), filter matrix extended, e2e updated.
5. **Docs and release note.** RFC 0027 §4.3, F08.1 D3 and RFC 015.00 §15.2 wording, the
   prune user docs. F08.1's mention of an "MCP prune command" is stale.

Steps 1 and 2 are independent and each ships alone. Step 2 writes files nothing reads, so
it is safe. Step 3 changes what `--older-than` and `--larger-than` select and step 4
adds the override, so ship them in the same release. Each step is its own PR.

## Failure modes

| Failure mode                                                             | Mitigation                                                                                                                                                      |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registration of an abandoned but existing workspace retains disk forever | `last_seen`, plus the follow-up list/forget command. Until then `--all` or `--include-referenced` frees it.                                                     |
| Moved or renamed workspace                                               | Its reference directory is `NotFound`, so it is not live and its checkouts become prunable; refetch, as today. Its registration stays until forgotten.          |
| Store shared into a container, WSL or CI runner                          | A `NotFound` path there never deletes the host's registration (prune never deletes one). The container's prune cannot protect the host's checkouts; documented. |
| Transient unreadable directory (unmounted drive, permissions)            | Treated as live.                                                                                                                                                |
| Race with a concurrent install                                           | Step 1 holds leases until references are written; prune re-reads inside the lock.                                                                               |
| A registration or reference file written by a newer omni                 | The consulting flags refuse and name the file; `--all` still works.                                                                                             |
| Older omni prunes without reading registrations                          | Same mixed-version gap as leases (D1); resolved or accepted in the D1 decision before step 3 ships.                                                             |
| Reference sets name entries that do not exist                            | Set lookup only, so harmless.                                                                                                                                   |
| Registration files hold absolute paths                                   | Per-user cache directory, same exposure as `.omni`. Note it in the docs.                                                                                        |
| Workspaces that never wrote references                                   | Unregistered, unprotected. The `--unused` help says so.                                                                                                         |

## Open questions for the maintainer

1. **D1.** Is "no store `VERSION` bump" still acceptable now that protection depends on
   every pruner reading `workspaces/`, or should step 3 bump to 2 so older omni refuses
   to prune? The plan assumes no bump and makes this a release gate.
2. **Windows.** Replacement of an open registration or reference file can fail
   transiently. Is bounded retry before failing closed acceptable? (Not verified; needs a
   Windows check in step 2/3.)
3. **Registration expiry.** Prune never deletes registrations. Is the follow-up
   `workspaces forget` enough, or should registrations whose reference directory has been
   `NotFound` for a long time (for example 90 days by `last_seen`) be reclaimed by a
   separate command?
4. **Release note scope.** Is the silent change in what `--older-than`/`--larger-than`
   select acceptable in a minor release, or should it ship behind `--unused` first and
   only change those filters in a later release?

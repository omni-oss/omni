# F08.7: Reference-driven retention (D3)

For source-manager contributors. Resolves decision D3 in
[F08.1](F08.1-lease-gc-reference-protocol.md): should `prune_store` protect
checkouts that workspaces reference? Builds on leases ([F08.3](F08.3-gc-honors-leases.md))
and the reference API ([F08.4](F08.4-atomic-reference-api.md)).
**Status:** plan, not started. Filter validation (the first step) is merged ([PR #193](https://github.com/omni-oss/omni/pull/193)).

## Assessment

- **Kind:** Large. It adds a store file format and lifecycle, changes two write paths
  (`update_ref_sets`, `reconcile_pins`) and prune, and touches the CLI, API and docs.
  It reverses the RFC 0027 §4.3 and F08.1 D3 position, so it needs a maintainer decision.
- **Risk:** High (deletion and retention in a shared store, a persistent format,
  concurrency). Independent review is required on every step.
- **Undo:** each step is revertable. A wrongly pruned checkout is refetched (network,
  and offline use breaks until re-install). Over-retention wastes disk and gives no signal.
- **Not decided here:** automatic prune, expiring registrations of workspaces that still
  exist.

## Problem

Prune reads no references, and references are per workspace (`<workspace>/.omni/sources/refs/*.json`)
while the store is shared per user. An idle checkout, one that no process holds a lease
on, is deleted by any prune, even when a workspace installed it for offline use. Making
prune read the pruning workspace's own references would not help: it would protect that
workspace's checkouts and delete every other workspace's (the failure RFC 0027 §3
recorded for `retain()`).

## Decisions taken

- **Registrations.** Each workspace registers itself in the store. A prune reads all
  registrations, so protection is store-wide.
- **`--all` is unchanged.** It selects every checkout (leased ones are still skipped).
  A new `--unused` selects only unused checkouts. No existing script changes meaning.
- **Age and size filters protect referenced checkouts by default.** The `.used` marker
  only changes on materialize, so an installed-but-idle checkout always looks old and
  `--older-than` would otherwise delete exactly what registrations keep. An override,
  `--include-referenced`, widens age and size filters.
- **Filter rules first.** Filter combinations are validated in the core (merged, #193). The
  new flags follow the same rules, in `StorePruneFilter::validate`.
- **Register on install and reconcile only** (`update_ref_sets`, `reconcile_pins`), not on
  materialize. Existing workspaces register when they next run `omni remote-sources install`.
- **No automatic expiry** of workspaces that still exist. A `workspaces` list/forget
  command is a separate follow-up.
- **No store `VERSION` bump.** `workspaces/` is additive. The registration carries its own
  `version` and `deny_unknown_fields`; an unknown newer version fails closed.

## Definition: unused

A checkout `(kind, slug, pin)` is **unused** when, at the moment prune evaluates it, all
three hold:

1. **No lease.** No process holds a `SourceLease` on it (prune's non-blocking exclusive
   lock succeeds). Otherwise it is in use (`skipped_in_use`).
2. **Not referenced.** No live registration lists that exact `(kind, slug, pin)`.
   Otherwise it is referenced (`skipped_referenced`).
3. **Registry readable.** Every registration parsed. A corrupt registration, or one from
   a newer version, makes prune refuse to run.

A registration is **live** unless its workspace path is definitively gone: it is live when
the path exists or when checking it fails with anything other than `NotFound` (uncertainty
keeps protection). A registration only lists what the workspace's current `refs/*.json`
reference, so an uninstalled or replaced pin disappears from it.

Unused does **not** mean old (the `.used` marker is only used by `--older-than`), does not
cover other users or machines (the store is per user), and does not cover workspaces that
have not registered yet. A moved workspace looks gone until it re-installs. It is a
snapshot, not a guarantee nothing needs the checkout later; a deleted checkout is refetched.

## Design

### Registration file

`<store>/workspaces/<hash(canonical workspace path)>.json`, written atomically.

- `version`, `path` (canonical absolute path, also kept to detect hash collisions),
  `last_seen`, and `checkouts`: a list of `(kind, slug, pin)`.
- Storing checkout ids rather than locators means prune never needs the driver registry,
  and an unregistered kind cannot be misread as unreferenced. The slug is known to the
  manager when the registration is written.
- Only the exact pin a workspace uses is protected, so a moved branch does not retain its
  old commit.

### Write path

- `update_ref_sets` and `reconcile_pins` rewrite the registration from the union of the
  workspace's `refs/*.json`, under the advisory lock they already hold. This keeps
  `ReplaceComplete` and empty-release semantics.
- It must not wait on a remote lock while holding the workspace lock.

### Prune

1. Validate the filter (including the new modifier).
2. Read all registrations without holding the workspace lock, and build the protected set.
3. For each selected entry: take the remote lock, then the lease (unchanged), and re-check
   the protected set inside the lock to narrow the race window.
4. Report protected entries as `skipped_referenced`, next to `skipped_in_use`.
5. Drop a registration only when its workspace path is a clean `NotFound`. Any other error
   (permissions, unmounted drive, network filesystem) keeps the registration and its
   protection. A corrupt registration fails closed: prune refuses to run.

### Lock order

Advisory lock (registration write, short) is never held while waiting on a remote lock.
Prune order stays remote lock, then lease. Reading registrations needs no lock because
files are replaced atomically.

## Behavior

| Flag                            | Selects                        | Referenced checkouts |
| ------------------------------- | ------------------------------ | -------------------- |
| `--all`                         | Every checkout                 | Included (unchanged) |
| `--unused`                      | Every unused checkout          | Protected            |
| `--older-than`, `--larger-than` | Checkouts matching age or size | Protected by default |
| `--include-referenced`          | Widens age and size filters    | Included             |

Leased checkouts are always skipped and reported as `skipped_in_use`.

Combination rules, enforced in `StorePruneFilter::validate` so the CLI and API share them:

| Combination                                                      | Result                                       |
| ---------------------------------------------------------------- | -------------------------------------------- |
| `--all` with `--unused`                                          | Reject (`--all` already includes everything) |
| `--all` with `--older-than` or `--larger-than`                   | Reject (already enforced)                    |
| `--unused` with `--older-than` or `--larger-than`                | Allow, ANDed                                 |
| `--include-referenced` with `--unused` or `--all`                | Reject (contradictory or redundant)          |
| `--include-referenced` without `--older-than` or `--larger-than` | Reject (nothing to widen)                    |
| Zero `--older-than` or `--larger-than`                           | Reject (already enforced)                    |

The response gains `skipped_referenced`, and the dry run lists referenced checkouts
separately so the user sees what `--include-referenced` would add. The CLI help for
`--unused` reads: "Select checkouts that no running command holds and no registered
workspace references. Workspaces register when you run `omni remote-sources install`."

`--unused` ships with step 5, after prune reads registrations. Before then it would behave
like `--all` and mislead.

## Known gap found while planning

Install contributors hold their leases only during manifest expansion (F08.5 batch 3).
`run_contributors` writes the reference sets after `contribute` returns
(`crates/omni_api/src/operations/remote_source.rs`), so a window exists where a freshly
installed checkout is neither leased nor registered. A prune in that window can delete it.
Fix before relying on registrations: hold the install's leases until `update_ref_sets`
(which writes the registration) has finished. Add a race test that fails without it.

## Steps

1. **Install holds leases until references are written.** Test: a pruner running
   continuously against an install never removes a checkout the install resolved.
2. **Registration format and write path.** Format with version, atomic write, union from
   `refs/*.json`. Tests: empty release, replace vs merge, corrupt file, concurrent updates.
3. **Prune reads registrations.** Protected set, `skipped_referenced`, fail-closed on a
   corrupt registration, re-check inside the lock. Tests: two workspaces on one store
   (A's prune keeps B's checkout; today it deletes it), stale path, unreadable path,
   moved pin, unknown kind.
4. **Registration cleanup.** Remove a registration only on a clean `NotFound`. Tests: path
   deleted, path unreadable, path recreated.
5. **API and CLI surface.** Override flag, `skipped_referenced`, regenerated command
   reference. No hand-edited generated files. Filter matrix extended.
6. **Docs and release note.** Update RFC 0027 §4.3, F08.1 D3 and RFC 015.00 §15.2 wording,
   the prune user docs and the e2e spec in `tests/omni-tests`. The release note states
   that `--all` now skips referenced checkouts.

Steps 1 and 2 are independent. Step 3 needs both. Each step is its own PR.

## Failure modes

| Failure mode                                                             | Mitigation                                                                                                     |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| Registration of an abandoned but existing workspace retains disk forever | `last_seen`, plus the follow-up list/forget command. Until then `--all` or `--include-referenced` frees it.    |
| Moved or renamed workspace looks deleted                                 | Its registration is dropped and its checkouts become prunable. The result is a refetch, as today. Document it. |
| Transient unreadable path (unmounted drive, container)                   | Treated as live, registration kept.                                                                            |
| Race with a concurrent install                                           | Step 1 closes the lease gap, and prune re-checks inside the lock.                                              |
| Registration naming an entry that no longer exists                       | Set lookup only, so it is harmless.                                                                            |
| Older omni prunes without reading registrations                          | Same mixed-version gap as leases (D1); no bump, documented in the release note.                                |
| Registrations hold absolute workspace paths                              | Per-user cache directory, same exposure as `.omni`. Note it in the docs.                                       |

## Follow-ups (not in this plan)

- `omni remote-sources workspaces` to list registrations (with `last_seen`) and forget
  them by path or age.
- Revisit "no `VERSION` bump" if mixed omni versions sharing one store become common.

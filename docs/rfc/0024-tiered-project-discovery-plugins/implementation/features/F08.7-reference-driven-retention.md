# F08.7: Reference-driven retention (D3)

For source-manager contributors. Resolves decision D3 in
[F08.1](F08.1-lease-gc-reference-protocol.md): should `prune_store` protect
checkouts that workspaces reference? Builds on leases ([F08.3](F08.3-gc-honors-leases.md))
and the reference API ([F08.4](F08.4-atomic-reference-api.md)).
**Status:** plan, revised after two independent review rounds (concurrency and contract). Not started. Filter validation, the first step, is merged ([PR #193](https://github.com/omni-oss/omni/pull/193)).

## Assessment

- **Kind:** Large. It adds a store file format and lifecycle, changes the install lease
  lifetime and the contributor trait, changes `update_ref_sets` and prune, and touches the
  CLI, API and docs. It reverses the RFC 0027 §4.3 and F08.1 D3 position, so it needs a
  maintainer decision.
- **Risk:** High (deletion and retention in a shared store, a persistent format,
  concurrency). Independent review is required on every step.
- **Undo:** each step is revertable, with two notes. Reverting step 1 means reverting the
  trait change across every contributor crate. After step 3 ships, reverting leaves
  registration files on disk that older readers ignore, which is harmless. A wrongly
  pruned checkout is refetched (network; offline use breaks until re-install).
  Over-retention wastes disk and gives no signal.
- **Not decided here:** automatic prune, expiring registrations of workspaces that still
  exist.

## Problem

Prune reads no references, and references are per workspace (`<workspace>/.omni/sources/refs/*.json`)
while the store is shared per user. An idle checkout, one that no process holds a lease
on, is deleted by any prune, even when a workspace installed it for offline use. Making
prune read only the pruning workspace's references would protect that workspace's
checkouts and delete every other workspace's (the failure RFC 0027 §3 recorded for
`retain()`).

## Decisions taken

- **Registrations are pointers.** Each workspace registers itself in the store with a
  small file that points at its reference directory. Prune reads that workspace's
  `refs/*.json` live. The registration holds no checkout list, so it cannot go stale.
- **`--all` is unchanged.** It selects every checkout (leased ones are still skipped).
  A new `--unused` selects only unused checkouts. No existing script changes meaning.
- **Age and size filters will protect referenced checkouts by default**, with an override
  `--include-referenced`. The `.used` marker only changes on materialize, so an
  installed-but-idle checkout always looks old and `--older-than` would otherwise delete
  exactly what registrations keep. This is a visible behavior change, so it ships as its
  own step and release note (step 5), after `--unused` has shipped.
- **Filter rules in the core.** Combinations are validated in `StorePruneFilter::validate`
  (#193); the new flags extend that function. The core field defaults to the protective
  behavior, so every `..Default::default()` caller is safe by construction.
- **Prune never deletes a registration**, and there is no automatic expiry. A
  `workspaces` list/forget command is a separate follow-up.
- **Store `VERSION`: decided, no bump** (maintainer, F08.1 D1). The layout change is
  additive. Protection only works if every pruner understands registrations, and an older
  omni deletes anything unleased, so the release note says so and the prune help warns.
- **Transient read errors:** reads of registration and reference files retry a bounded
  number of times (about 3, short sleeps) before failing closed. This is platform-neutral
  wording on purpose. It matters most on Windows, where replacing a file that another
  process (antivirus, an indexer, an editor) has open without delete-sharing can fail,
  whereas on Linux and macOS a rename over an open file just succeeds. Unverified on
  Windows; it goes on the release checklist.

## Definition: unused

A checkout `(kind, slug, pin)` is **unused** when, at the moment prune evaluates it, all
three hold:

1. **No lease.** No process holds a `SourceLease` on it (prune's non-blocking exclusive
   lock succeeds). Otherwise it is in use (`skipped_in_use`).
2. **Not referenced.** No live registration's reference sets name that exact
   `(kind, slug, pin)`. Otherwise it is referenced (`skipped_referenced`).
3. **Registry readable.** For flags that consult registrations, every registration and
   the reference sets it points at could be read. See "Failure handling".

A registration is **live** when its reference directory exists, or when checking it
fails with anything other than `NotFound` (uncertainty keeps protection for that run).
A `NotFound` registration is **not live for this run** and is left on disk.

Unused does **not** mean old (the `.used` marker is only used by `--older-than`), does not
cover other users, and does not cover workspaces that have not registered. It is a
snapshot, not a guarantee nothing needs the checkout later; a deleted checkout is
refetched. Specifically unprotected:

- A workspace that never wrote references, or wrote them before step 2 shipped, until it
  next runs install or a generator or tool run that writes references. This includes the
  pruning workspace itself.
- Runs that never write references, for example a targeted projection sync
  (`projection.rs` deliberately writes none): the checkout is protected only while its
  lease lives.
- A workspace whose reference directory is not visible from where prune runs.

## Design

### Registration file

`<store>/workspaces/<hash(normalized lockfile path)>.json`.

- `version` (`1.0.0`, `deny_unknown_fields`), `lockfile_path` (the normalized absolute
  path), `last_seen`.
- **Keyed on the lockfile path, not the workspace path.** The reference directory is
  `lockfile_path.parent()/refs`, which is what keeps checkouts needed, and the manager
  already holds `lockfile_path`, so no config field is needed. A workspace directory that
  still exists but whose `.omni/sources` was wiped is correctly not live.
- **Normalization:** canonicalize (resolves symlinks) and, on Windows, strip the `\\?\`
  verbatim prefix; this is a small, unit-testable function. Do **not** case-fold: a
  duplicate registration for the same workspace is harmless because protection is a
  union. Use a full-width hash. A file whose stored `lockfile_path` does not match its
  hash is treated as a collision and fails closed for the consulting flags.
- A second workspace at the same path overwrites the first, which is correct.

### Write path

- **Written inside `update_ref_sets`, as the first file of the same `write_batch`**, under
  the advisory guard and inside the owned `spawn_blocking`. `<store>/workspaces` is created
  before the batch. A crash can then leave a registration without refs (harmless: a
  missing reference directory means not live) but never refs without a registration.
- Not written from `reconcile_pins`: it only reads refs and the lockfile and never touches
  the store, so it adds nothing and widens the failure surface. `persist_pins` and `lock()`
  also do not register.
- Every `update_ref_sets` registers, so install and the lazy generator and tool runs both
  do. `update_ref_sets` returns early for an empty `updates` slice; that case does not
  register.
- An empty release (a subsystem with an empty reference list) still writes the
  registration; it never deletes it.
- The `write_batch` renames files one at a time, so a reader of `refs/*.json` can see a
  prefix of a batch. Cross-file atomicity is not claimed. Install is covered by its lease,
  and a crash mid-batch converges on re-run.

### Prune

1. Validate the filter.
2. Consult registrations only for flags that need them (`--unused`, and after step 5 the
   age and size filters without `--include-referenced`). `--all` and
   `--include-referenced` do not read registrations.
3. For each selected entry: take the remote lock, then the lease with try-lock (unchanged),
   then **re-read the registrations and the `refs/` directories they point at while still
   holding both**, and skip the entry if it is now referenced. A cached set is not
   enough. With step 1, an install either holds the lease (the try-lock fails) or has
   finished writing its references (the re-read sees them). The re-read reads only
   `refs/` files, because it does I/O, possibly on slow paths, while holding the remote
   lock and stalls installs of that remote.
4. A separate tolerant reader parses foreign reference files; do not reuse
   `prepare_ref_set` or `reconcile_pins`, which call `check_kind` and fail on unknown
   kinds. Each reference `kind -> locator -> selector -> {pin}` is mapped to
   `(kind, safe_slug(driver.slug(SourceSpec{locator, selector})), pin)` with the pruner's
   own drivers; the selector must be included because a custom driver's slug may depend
   on it. A reference to a kind the pruner has no driver for is ignored, because
   `store_entries` lists only registered kinds. A pin that fails `is_safe_segment` in a
   foreign file fails closed for the consulting flags.
5. Report protected entries as `skipped_referenced`. The CLI's confirmed second pass
   (`only`) re-checks the protected set instead of trusting the dry run.

### Registration lifecycle

- **Prune never deletes a registration.** A `NotFound` reference directory may only mean
  the path is not visible from where prune runs (a bind-mounted store inside a container,
  WSL or a CI runner), and deleting would permanently strip the host's protection. It is
  treated as not live for that run only.
- Registrations accumulate for removed worktrees and ephemeral CI workspaces. They are
  tiny. The follow-up `workspaces` forget command reclaims them by path or by `last_seen`.
- A pruner that cannot see a workspace cannot protect its checkouts; documented.
- A workspace that uses different stores registers in each; a reference to a checkout
  that is not in a given store is harmless.

### Failure handling

- A corrupt registration or reference file, and a file from a newer version, both surface
  as one parse error that names the file. The consulting flags refuse to run.
  `--all` and `--include-referenced` still work, so the escape hatch never depends on the
  registry being healthy.
- A transient read failure, or a registration file replaced between listing and reading,
  is retried briefly; only a persistent error fails closed.

### Lock order

- Install: remote lock, then a shared lease (held for the whole install), then the
  advisory lock in `update_ref_sets`. Nothing under the advisory lock waits on a remote
  lock or lease.
- Prune: remote lock, then try-lock on the lease, then lock-free reads of registration and
  reference files. It never takes the advisory lock, and never waits on a lease, so there is
  no cycle with a lease holder that later waits on another remote lock.
- Registration files are replaced atomically (`write_batch`), so reading needs no lock.

## Behavior

| Flag                            | Selects                        | Referenced checkouts                             |
| ------------------------------- | ------------------------------ | ------------------------------------------------ |
| `--all`                         | Every checkout                 | Included (unchanged)                             |
| `--unused`                      | Every unused checkout          | Protected                                        |
| `--older-than`, `--larger-than` | Checkouts matching age or size | Included until step 5, then protected by default |
| `--include-referenced` (step 5) | Widens age and size filters    | Included                                         |

Leased checkouts are always skipped and reported as `skipped_in_use`.

Combination rules, enforced in `StorePruneFilter::validate` so the CLI and API share them:

| Combination                                                      | Result                                                                                                                                                                                |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--all` with `--unused`                                          | Reject (`--all` already includes everything)                                                                                                                                          |
| `--all` with `--older-than` or `--larger-than`                   | Reject (already enforced)                                                                                                                                                             |
| `--unused` with `--older-than` or `--larger-than`                | Reject. A deliberate simplification: once step 5 lands the age and size filters already skip referenced checkouts, so the pair is redundant; "unused and old" is just `--older-than`. |
| `--include-referenced` with `--unused` or `--all`                | Reject (contradictory or redundant)                                                                                                                                                   |
| `--include-referenced` without `--older-than` or `--larger-than` | Reject (nothing to widen)                                                                                                                                                             |
| Zero `--older-than` or `--larger-than`                           | Reject (already enforced)                                                                                                                                                             |

### Core and API changes

- `StorePruneFilter` (still `Copy`) gains `unused: bool` and `include_referenced: bool`,
  both defaulting to false. `has_criteria` includes `unused`; `validate` implements the
  table. About 15 existing struct literals use `..Default::default()` and stay valid.
- `PruneReport` gains `skipped_referenced`. `RemoteSourcesPruneRequest` and
  `RemoteSourcesPruneResponse` get `#[serde(default)]` on every new field. `all` and
  `dry_run` have no serde default today; leave them.
- The API handler's "refusing to prune without a filter" message and `has_criteria` name
  `--unused`.
- CLI: `--unused` has `conflicts_with_all = [all, older_than, larger_than]`.
  `--include-referenced` has `conflicts_with_all = [all, unused]` and an `ArgGroup` so it
  requires `--older-than` or `--larger-than` (clap's `requires_all` is not an "any of").
  The messages name those flags. The CLI messages, which today say only "in use or
  failed", mention referenced checkouts and the dry run lists them separately.
- The command reference under `apps/site/content/docs/references/commands/omni/remote-sources/prune`
  is generated; regenerate it, never hand-edit.
- There is no MCP prune tool, so no MCP change. F08.1's "MCP prune command" is stale.
- `--unused` help: "Select checkouts that no running command holds and no registered
  workspace references. Workspaces register when they write references (install, or a
  generator or tool run)."

### Release notes

- Step 4: `--unused` is new. `--all`, `--older-than` and `--larger-than` are unchanged.
  Older omni versions prune without reading registrations. Workspaces register when they
  next write references.
- Step 5: `--older-than` and `--larger-than` now skip checkouts referenced by a registered
  workspace. Scripts that relied on them to reclaim a workspace's checkouts stop doing so
  once that workspace has run install, with no signal. `--include-referenced` restores the
  old selection.

## Install lease scope (step 1)

Install is unprotected in a wide window:

- Generator and tool contributors take **no lease at all** (`materialize_flat_remote` in
  `omni_remote_source_contributors/src/lib.rs` calls the unleased `materialize`). Pack nodes
  also reach it three times inside pack's own `contribute`.
- Projection and pack-expansion leases are dropped inside `contribute`.
- `RemoteSourceContributor::contribute` returns only `Vec<RemoteSourceRef>`, so leases
  cannot be returned, and contributors run one after another with earlier results unleased.
- The window spans network fetches and ends only after `update_ref_sets`.

The fix:

- `run_contributors` owns one `LeaseSet` for the whole install and passes it to every
  contributor, which materializes with `materialize_into`. This includes the flat
  generator and tool paths, and pack's own nodes and `expand_packs`.
- The set is dropped explicitly after `update_ref_sets` returns. `reconcile_pins` reads
  refs and the lockfile and never touches the store, so it does not need the leases.
- `LeaseSet` deduplicates by `(kind, slug, pin)`. Each `materialize_into` call otherwise
  opens a new descriptor, so descriptors scale with source references (pack nodes times
  generators, tools and projections), not with distinct checkouts, and macOS defaults to 256.
- The trait change touches the four contributor implementations, the mockall automock in
  `contributor.rs`, the implementations and the call in `omni_api/.../remote_source.rs`,
  and test call sites in `omni_remote_source_contributors/tests` (including
  `support/install_leases.rs`). Grep for other implementors first.
- Extend the invariant test in `omni_api/.../remote_source.rs` that forbids `.materialize(`
  to cover the contributors crate. `lib.rs` is the current violator.
- Lazy generator and tool runs already return their `LeaseSet` after `update_refs`, so
  they are fine.

## Steps

1. **Install owns one deduplicating `LeaseSet` until `update_ref_sets` returns.** Trait
   change and the flat paths. Tests: a pruner running continuously against an install
   never removes a checkout the install resolved, including a generator-only install,
   which is unleased today; the test fails without the change. Descriptor count with
   many references.
2. **Registration format and write path.** First file of the `update_ref_sets`
   `write_batch`. Tests: written on first write, idempotent, survives an empty release,
   not written for empty `updates`, hash and stored-path mismatch detected, normalization
   (Windows prefix, symlink), corrupt existing file, failure injection (an unwritable
   `workspaces` directory) leaves the previous state and a registration never without its
   refs ordering reversed.
3. **Prune engine reads registrations and references.** Protected set, tolerant reader,
   in-lock re-read, drivers-based mapping with selector, failure handling, confirmed-pass
   recheck, `skipped_referenced`. The API handler sets `include_referenced: true` for age
   and size filters, so behavior is unchanged for existing flags. Tests build two managers with different lockfile paths on one store root: A's
   prune keeps B's checkout (today it deletes it); missing reference directory (not live,
   registration kept); unreadable directory (live); moved pin; unknown kind; custom
   driver whose slug depends on the selector (`fake_kind`); corrupt registration refuses
   the consulting flags but not `--all`; a registration written between the dry run and
   the confirmed pass. Windows retry cannot be tested here.
4. **`--unused` and the report.** CLI flag, clap conflicts, `skipped_referenced` in the
   API and CLI output, extended validation and matrix, regenerated reference, e2e cases
   for `--unused` against a referenced and an unreferenced checkout. Ships after step 3.
5. **Age and size filters protect referenced checkouts; add `--include-referenced`.** Flip
   the API default, add the flag, the clap group, e2e for `--older-than` against a
   referenced checkout. Own release note. Revisit scope with the maintainer before it
   ships (see Open questions).
6. **Docs.** RFC 0027 §4.3, F08.1 D3 and RFC 015.00 §15.2 wording, the prune user docs.

Steps 1 and 2 are independent and each ships alone. Step 2 writes files nothing reads, so
it is safe. Steps 3 and 4 may ship together or separately. Each step is its own PR.

## Failure modes

| Failure mode                                                             | Mitigation                                                                                                                                             |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Registration of an abandoned but existing workspace retains disk forever | `last_seen`, plus the follow-up list/forget command. Until then `--all` frees it.                                                                      |
| Moved or renamed workspace                                               | Its reference directory is `NotFound`, so it is not live and its checkouts become prunable; refetch, as today. Its registration stays until forgotten. |
| Store shared into a container, WSL or CI runner                          | A `NotFound` path there never deletes the host's registration. The container's prune cannot protect the host's checkouts; documented.                  |
| Transient unreadable directory (unmounted drive, permissions)            | Treated as live.                                                                                                                                       |
| Race with a concurrent install                                           | Step 1 holds leases until `update_ref_sets` returns; prune re-reads inside the lock.                                                                   |
| Crash or cancellation between writes of one batch                        | The registration is the first file, so refs without a registration cannot occur; a prefix converges on re-run.                                         |
| A registration or reference file written by a newer omni                 | The consulting flags refuse and name the file; `--all` still works.                                                                                    |
| Older omni prunes without reading registrations                          | Same mixed-version gap as leases (D1); resolved or accepted in the D1 decision before step 3 ships.                                                    |
| Reference sets name entries that do not exist                            | Set lookup only, so harmless.                                                                                                                          |
| Registration files hold absolute paths                                   | Per-user cache directory, same exposure as `.omni`. Note it in the docs.                                                                               |
| Workspaces or runs that never wrote references                           | Unregistered, unprotected. The `--unused` help says so.                                                                                                |
| File descriptor exhaustion in a large install                            | `LeaseSet` dedupes by checkout; test with many references.                                                                                             |

## Open questions for the maintainer

Each has a default the plan proceeds with.

1. **Transient read errors.** Default: bounded retry (about 3 tries), then fail closed for
   the consulting flags only; on the release checklist for Windows.
2. **Registration cleanup.** Default: none in this plan. The `workspaces` list/forget
   command is a follow-up, needed only for workspaces that still exist but are abandoned
   (a `NotFound` workspace stops protecting anything by itself) and for tidiness. Until it
   exists, deleting the registration file under `<store>/workspaces/` releases a workspace.
3. **Release scope.** Default: ship `--unused` first (step 4); the change to what
   `--older-than` and `--larger-than` select is a separate later step (step 5) with its
   own release note.

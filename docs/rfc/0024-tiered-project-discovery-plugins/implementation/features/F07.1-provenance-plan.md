# F07 plan: provenance redesign first, conflict detection second

**Reader:** the maintainer approving F07, then the implementer. **Status:** revised after the maintainer chose the full redesign; needs a final go-ahead
(High risk). **Decision already taken:** two PRs, the provenance/metadata redesign
first, conflict detection second ([F07](F07-conflict-detection-and-provenance.md)).

**Risk: High.** The work changes config composition and the loader core. The first slice
also moves the origin that error messages use for `cache.enabled`. The effective value and
cache keys must not change; that is what the checks below prove.

## Where things stand (code)

- `CacheLayer.enabled_file: Option<Arc<OmniPath>>` (`omni_configurations/src/layer.rs`) is
  loader data on an authored type. `ProjectLayer::load` stamps it; `impl Merge for CacheLayer`
  copies it with `enabled`.
- `finalize_composed` reads it back per task into `FinalizedProject.task_cache_enabled_file`,
  which flows through `project_data_extractor` to `LoadedContext::cache_enabled_file`.
- Project-level layers are merged (`LoadedLayer::merge`), so after composition a plain value
  cannot say which file supplied it. Task declarations are different: `TaskDeclarations` keeps
  the ordered `Arc<TaskLongFormLayer>` list.
- `LoadedLayer { file, dir, layer }` and the ordered layer list from `project_config_loader.rs`
  (R04.2, R07.2) already carry the file for every declaration.
- `ProjectConfiguration.file` and `.dir` are loader-supplied fields on the public config type.

## The design: composition is one replay that outputs both values and provenance

Decided with the maintainer: do the full redesign, not a stopgap. Option C (a separate
provenance walk beside the merge) was rejected because two loops that must agree will
eventually drift, and every later field would repeat the problem.

- **Declarations carry their origin.** `LoadedLayer` already has `file` and `dir`. Give it an
  `Origin` (layer identity, `Option<Arc<OmniPath>>` for the declaring file, base directory)
  and treat each loaded layer as an immutable, ordered declaration, as `TaskDeclarations`
  already does for tasks. Sources without a file stay distinct from file-backed ones.
- **One replay.** Composition becomes an explicit `replay(&[&LoadedLayer])` over the ordered
  raw layers (`LoadedProjects::raw_layers` already exposes that order). The same loop folds
  authored values and records provenance, so the winning origin is by construction the layer
  whose operation produced the effective value. It replaces the `Merge` impl on `LoadedLayer`
  that the extension graph uses today. Provenance is an output of replay, never a separately
  merged map.
- **Provenance record.** `Provenance` maps a structured `FieldPath` (project, task, field
  components) to the winning `Origin` for scalar replacement, and keeps the surviving
  contributions where collections need them (the F07.3 conflict model builds on this).
- **Tracked fields are an explicit list**, not hidden struct fields: `cache.enabled` first,
  then whatever the F07.3 conflict rules and diagnostics need.
- **Authored types become pure again.** Remove `CacheLayer.enabled_file`, its custom `Merge`
  and the stamping in `ProjectLayer::load`; `CacheLayer` merges by value. The resolved
  project (not the authored type) carries runtime location, which is slice F07.2.
- **Consumers read explicit types.** `LoadedContext::cache_enabled_file`, F05.2's error and
  `omni cache eligibility` read the provenance output; nothing reconstructs it from
  serialized config.

## Sketches (illustrative, not final signatures)

Types, in `omni_configurations`:

```rust
/// Where one declaration came from. Built once, when a layer is loaded.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Origin {
    pub layer: LayerId,                 // stable identity of the declaration
    pub file: Option<Arc<OmniPath>>,    // None for sources without a file
    pub base_dir: OmniPath,             // for inherited relative paths; not the project root
}

/// Structured, never delimiter-joined: `a#b` + `c` and `a` + `b#c` stay distinct.
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct FieldPath {
    pub project: Arc<str>,
    pub task: Option<Arc<str>>,
    pub field: TrackedField,
}

/// The explicit list of fields that have provenance. Adding one is a visible change.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum TrackedField {
    CacheEnabled,
    // F07.3 adds the fields conflict detection needs.
}

/// Output of replay. Never merged separately and never serialized with the config.
#[derive(Debug, Clone, Default, PartialEq)]
pub struct Provenance {
    winners: HashMap<FieldPath, Origin>,
}

impl Provenance {
    pub fn origin(&self, path: &FieldPath) -> Option<&Origin> { self.winners.get(path) }
}
```

`LoadedLayer` gains the origin and stays an immutable declaration (today it is `{ file, dir,
layer }` and implements `Merge`; that impl goes away):

```rust
pub struct LoadedLayer {
    pub origin: Origin,   // replaces the loose `file` / `dir`; accessors keep old callers working
    pub layer: ProjectLayer,
}
```

The single replay, which replaces the extension graph's `Merge`-based composition:

```rust
pub struct Composed {
    pub layer: ProjectLayer,       // effective authored values, merged by value
    pub provenance: Provenance,    // produced in the same loop
}

/// `layers` is the ordered extension closure (what `raw_layers` returns today),
/// ending with the concrete file.
pub fn replay(layers: &[&LoadedLayer]) -> Composed {
    let mut layer = ProjectLayer::default();
    let mut provenance = Provenance::default();
    for declaration in layers {
        record_tracked(&mut provenance, &declaration.origin, &declaration.layer);
        layer.merge(declaration.layer.clone());    // same loop, same order
    }
    Composed { layer, provenance }
}

/// An explicit value replaces the winner; an omitted one leaves it alone.
fn record_tracked(p: &mut Provenance, origin: &Origin, layer: &ProjectLayer) {
    if layer.cache.as_ref().is_some_and(|c| c.enabled.is_some()) {
        p.winners.insert(project_field(layer, TrackedField::CacheEnabled), origin.clone());
    }
    for (name, task) in layer.declared_tasks() {   // long-form declarations, in order
        if task.cache().is_some_and(|c| c.enabled.is_some()) {
            p.winners.insert(task_field(layer, name, TrackedField::CacheEnabled), origin.clone());
        }
    }
}
```

`CacheLayer` becomes plain again (no `enabled_file`, no custom `Merge`; `#[derive(Merge)]`
returns), and `ProjectLayer::load` no longer stamps a file. Finalization reads the output:

```rust
impl FinalizedProject {
    pub fn cache_enabled_origin(&self, task: &str) -> Option<&Origin> { /* from provenance */ }
}
// LoadedContext::cache_enabled_file keeps its signature and reads this instead of
// `task_cache_enabled_file`.
```

The agreement test that guards the replay, written before the old merge is removed:

```rust
#[test]
fn replay_agrees_with_the_old_merge() {
    for layers in generated_layer_sets() {            // omitted, equal-value, file-less, diamonds
        let old = layers.iter().cloned().reduce(|mut a, b| { a.merge(b); a }).unwrap();
        let new = replay(&layers.iter().collect::<Vec<_>>());
        assert_eq!(old.layer, new.layer);
        assert_eq!(old.finalize_composed()?.task_cache_enabled, new_finalized.task_cache_enabled);
    }
}
```

One open point in this sketch: `record_tracked` still states the "explicit value replaces"
rule once more next to the merge. It is a single, named rule in one place, and the agreement
test pins it to the merge; the alternative, a tracking variant of every `Merge` impl, is the
heavier option F07.3 may need and the plan leaves it for then.

## Slices

1. **F07.1: origin types and replay-derived provenance (L, High).**
   - Add `Origin` and `FieldPath` and the single `replay`; derive cache-enabled provenance
     from it; remove the hidden field, custom merge and stamping; keep the accessor.
   - Replace the generic extension-graph merge of `LoadedLayer` with the replay (the graph
     keeps providing order and cycle detection).
   - Checks: omitted, equal-value and file-less replacements; task and project inheritance;
     `extends` chains and diamonds; names containing `#`; a property test that the replay's
     effective values equal the old merge's for generated layer sets (before removal);
     schema and serialization parity; effective values and cache keys unchanged
     (old-versus-new hash fixtures); F05.2 messages unchanged.
2. **F07.2: project file and directory boundary (M, High, own PR, in scope).** Move `.file`
   and `.dir` off `ProjectConfiguration` into the resolved project. Audit every caller that
   reads, hashes or displays them first. Test relative paths, extension closure order and
   virtual roots without a physical file.
3. **F07.3: conflict model (L, High, second PR).** Contributor layers merged in stable id
   order; a `Conflict { field_path, contributors }` marker; identical values coalesce,
   differing scalar or task-field values conflict; explicit chains stay last-wins; markers
   survive an unrelated override and are resolved only by an explicit operation on that
   field or subtree (C12); interpretation-mode-aware equality; shuffled-order property tests.
4. **F07.4: diagnostics (S).** A diagnostic naming both contributors, files and the field path.
5. **F07.5: inspection output (S).** Surface provenance in `omni cache eligibility` and its
   MCP tool where cheap; the full surface stays F09.

# F07 plan: provenance redesign first, conflict detection second

**Reader:** the maintainer approving F07, then the implementer. **Status:** proposed, needs
approval (High risk). **Decision already taken:** two PRs, the provenance/metadata redesign
first, conflict detection second ([F07](F07-conflict-detection-and-provenance.md)).

**Risk: High.** The work changes config composition and the loader core. The first slice
also moves the origin that error messages use for `cache.enabled`. The effective value and
cache keys must not change; that is what the checks below prove.

## Where things stand (code)

- `CacheLayer.enabled_file: Option<Arc<OmniPath>>` (`omni_configurations/src/layer.rs`) is
  loader data on an authored type. `ProjectLayer::load` stamps it; `impl Merge for CacheLayer`
  copies it with `enabled`.
- `finalize_composed` reads it back per task into `FinalizedProject.task_cache_enabled_file`,
  which flows through `project_data_extractor` to `LoadedContext::cache_enabled_file`.
- Project-level layers are merged (`LoadedLayer::merge`), so after composition a plain value
  cannot say which file supplied it. Task declarations are different: `TaskDeclarations` keeps
  the ordered `Arc<TaskLongFormLayer>` list.
- `LoadedLayer { file, dir, layer }` and the ordered layer list from `project_config_loader.rs`
  (R04.2, R07.2) already carry the file for every declaration.
- `ProjectConfiguration.file` and `.dir` are loader-supplied fields on the public config type.

## The one design choice

How should provenance be produced so it cannot disagree with the effective value?

| Option | How | Cost |
| --- | --- | --- |
| A. Keep hidden fields | One loader field per tracked setting plus a custom merge each | Already hurts at one field; stale origins are easy to leave behind |
| B. Origin carried by each declaration, replay emits provenance | Wrap loaded declarations with an `Origin`; the replay that computes effective values also writes a provenance record | Right shape, widest change: project-level layers need ordered declarations like tasks have |
| C. Provenance log from the same ordered layer list | Walk the ordered `LoadedLayer` list once, applying "an explicit value replaces, an omitted one does not", and emit effective value and origin together from that single walk | Smaller; the walk and the merge must agree, which a test enforces |

**Recommendation: C for the first slice, shaped so it can grow into B.** It removes the
hidden field and the custom merge without changing how layers merge. The rule that both
paths must agree is checked by a test that compares the log's winning value to the merged
layer's value for every combination of omitted, equal-value and file-less declarations.
Move to B only when conflict detection (the second PR) needs per-contribution origins.

## Slices

1. **F07.1: origin types and cache-enabled provenance (M, High).**
   - Add `Origin` (layer identity, declaring file as `Option<Arc<OmniPath>>`, base directory)
     and a structured `FieldPath` (project, task, field; no delimiter-joined strings).
   - Produce cache-enabled provenance from the ordered layer walk; drop
     `CacheLayer.enabled_file`, its custom `Merge` and the `ProjectLayer::load` stamping.
     Keep `LoadedContext::cache_enabled_file` and its callers (F05.2 error, F09 inspection).
   - Checks: omitted, equal-value and file-less replacements; task and project inheritance;
     `extends` chains; names containing `#`; schema and serialization parity; effective
     values and cache keys unchanged (hash fixtures before and after).
2. **F07.2: project file and directory boundary (M, optional, own PR).** Move `.file` and
   `.dir` off `ProjectConfiguration` into the resolved project. Audit every caller that reads,
   hashes or displays them first. Test relative paths, extension closure order and virtual
   roots without a physical file. Decide in the F07.2 PR, not now, whether to do it at all.
3. **F07.3: conflict model (L, High, second PR).** Contributor layers merged in stable id
   order; a `Conflict { field_path, contributors }` marker; identical values coalesce,
   differing scalar or task-field values conflict; explicit chains stay last-wins; markers
   survive an unrelated override and are resolved only by an explicit operation on that
   field or subtree (C12); interpretation-mode-aware equality; shuffled-order property tests.
4. **F07.4: diagnostics (S).** A diagnostic naming both contributors, files and the field path.
5. **F07.5: inspection output (S).** Surface provenance in `omni cache eligibility` and its
   MCP tool where cheap; the full surface stays F09.

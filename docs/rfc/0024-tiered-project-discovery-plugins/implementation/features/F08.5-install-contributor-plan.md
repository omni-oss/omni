# F08.5 batch 3: install contributor lease plan

**Status:** approved by the user; implemented, pending independent PR review.
**Kind / risk:** Medium / High (checkout lifetimes and concurrent pruning).

## Goal and assessment

Protect checkout files read by install contributors for the whole manifest
expansion. This completes the install-reader part of F08.5 without changing
reference publication, cache keys, lockfiles, or the contributor trait.

- **Extent:** projection contributor expansion and contributor tests, plus tracking
  docs. Pack expansion already owns a `LeaseSet`; flat generator/tool contribution
  materializes sources and copies pins but does not read checkout files.
- **Unknowns:** whether a deterministic filesystem-read barrier can exercise nested
  manifest discovery with the existing system-traits test facilities.
- **Undo:** revert this slice; no format or persistent-data migration.
- **People / time:** one bounded implementation slice, followed by independent PR
  review before merge. No implementation agents are needed.
- **Main failure guarded against:** prune removes a checkout after materialization
  but before projection discovery reads its manifest or a local child manifest.
- **Escalation:** stop and re-plan if this requires manager changes, a contributor
  trait change, or a retention guarantee beyond file-reading lifetimes.

## Findings

`ProjectionRemoteContributor::contribute` builds `MaterializeOnlyExpand`.
Its `classify` uses plain `materialize`, then reads the checkout through
`discover_owned_manifest`. It also follows local children inside git checkouts.
No lease protects those reads.

`PackRemoteContributor` keeps `ExpandedPacks` alive while collecting its child
sources. That value already owns the leases for pack manifest roots.
`materialize_flat_remote` only returns source/pin pairs; it does not discover or
open checkout files. Do not add unnecessary leases solely to eliminate every
plain `materialize` call.

## Implementation and verification

1. Give the projection expander an operation-scoped `LeaseSet` and use
   `materialize_into` before manifest discovery. Keep all leases until expansion
   finishes, including nested local-manifest reads. No contributor signature or
   returned-value changes.
2. Add a deterministic real-git test, with a barrier at manifest reading rather
   than a timing sleep. While expansion is paused, pruning must skip its leased
   checkout and reclaim an unrelated unleased checkout. After completion,
   pruning may reclaim it. Cover an expansion error releasing the leases too.
3. Audit pack contribution lifetime and add a regression check if existing pack
   tests do not protect the contributor path. Document why flat contributors do
   not need a reader lease.
4. Run contributor and remote-source suites, scoped clippy/format checks, and
   API/CLI/MCP test-target compilation. Remove the lease wiring temporarily
   using a file backup: the new regression must fail without it. Platform lock
   behavior beyond Linux remains for CI. Update F08.5 status and task tracking.

Uses the existing approved F08.1 lease protocol. Independent PR review is required
before merge.

## Non-goals

- Keeping checkouts alive after their last read merely because refs are about to
  be published: reference publication and checkout retention are separate.
- Store VERSION changes (D1), reference-driven retention (D3), stale pending
  cleanup (D7), new lock ordering, or cross-file rollback.
- F04 exact selectors, which can be developed independently but change CLI/MCP
  request behavior and need their own migration plan.

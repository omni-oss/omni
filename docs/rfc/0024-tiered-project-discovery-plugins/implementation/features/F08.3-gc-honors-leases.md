# F08.3: Prune honors leases

For source-manager contributors. Implements the acquisition and GC interaction in
[F08.1](F08.1-lease-gc-reference-protocol.md) on top of the
[F08.2](F08.2-lease-primitive.md) primitive.
**Status:** merged ([PR #111](https://github.com/omni-oss/omni/pull/111)).

## Assessment and plan

- **Kind / risk:** Medium / High (deletion, shared state and concurrency).
- **Extent:** `omni_remote_source` manager (acquisition, prune, report types), the
  one production caller in `omni_api`, and the CLI prune output. No persisted
  format changes.
- **Unknowns:** the publish-to-lease and fast-path-to-lease gaps. A race test with a
  continuously pruning peer is the check; it must fail without the lease.
- **Undo:** revert. Leases are empty files and add no format; prune returns to
  lease-blind deletion.
- **Execution:** solo, with independent review before merge.
- **Out of scope:** contributor/caller migration to `materialize_leased` and
  install sequencing (F08.5), reference-driven retention (D3), `.pending` cleanup
  (D7), and the store `VERSION` bump (D1, below).

## Behavior

- `materialize_leased` returns `LeasedSource { source, lease: Arc<SourceLease> }`.
  The fast path takes the lease before the completeness check; the slow path takes
  it while still holding the remote lock. `materialize` is unchanged and takes no
  lease, so existing callers do not gain protection until F08.5 migrates them.
- `prune_store_report` takes, per entry, the remote lock and then the lease
  exclusively without waiting (never the reverse). A held lease means the entry is
  `skipped_in_use`; unrelated entries in the same run, including under `all`, are
  still removed. `prune_store` keeps its signature and returns only the removed
  entries.
- Removal is manifest first, then the tree, then the `.used` marker. A failed
  removal is recorded in `failed` and the run continues; what remains reads as
  incomplete and is re-published on next use. An unsafe directory name cannot map
  to a lease file, so it is reported as failed rather than deleted uncoordinated.
- Once both guards are held, the removal runs in an owned task that keeps them until
  it finishes, so cancelling the caller cannot let a peer publish and lease a
  replacement that the abandoned removal then deletes.
- A dry run is lock-free: it probes only existing lease files without creating any
  and reports would-remove and would-skip.
- The raw-cache and remote-directory cleanup is unchanged: a leased tree keeps its
  parent non-empty.
- `handle_remote_sources_prune` migrates to the report. The response gains
  additive `skipped_in_use` and `failed` lists. The CLI lists skipped checkouts as
  notices and, after printing what was removed, prints each failure and exits
  non-zero.

## Decisions

- D1 (store `VERSION` bump): **not made here; left open.** An older omni ignores
  `leases/` and can still prune a leased checkout. Bumping the layout version would
  stop older omni using the shared per-user store at all, so it needs the release
  owner. Until then the lease protects against this omni's prune only.
- D2: lease files are never unlinked.
- D3: prune still does not consult reference sets.

## Verification

- `tests/gc_leases.rs` (real filesystem): leased skip with unleased reclaimed in
  one run, `only`, dry run without creating lease files, lease surviving reference
  removal and reconciliation, last-owner release, re-publish after prune, and a
  reader/prune race. The race test fails when prune ignores leases (checked by
  mutation) and passes repeatedly with them.
- `tests/gc_cancel.rs`: aborting a prune mid-removal leaves the lease and remote lock
  held until the removal finishes (fails on the previous code).
- Unix failure tests: a partial removal is reported, the run continues and the
  leftover never reads as complete; an unremovable manifest leaves the checkout
  intact. They skip when permissions are not enforced (running as root).
- `omni_api` unit test for the response mapping, including the additive wire form.
- Not covered by an automated test: the CLI exit code and the end-to-end command.

## Limits

Advisory locks protect only cooperating omni processes on filesystems with working
locks; `rm -rf` and older omni ignore a lease. The dry run is a snapshot. A
removal that fails part-way can leave an inert incomplete tree.

# F08.2: Lease primitive

For source-manager contributors implementing the F08.3 acquisition/GC protocol.
**Status:** implemented, pending PR review.

## Assessment and plan

- **Kind / risk:** Medium / High (cross-process shared-state contract).
- **Scope:** add non-blocking exclusive locking and an owned, shareable source
  lease. Existing materialization, pruning and callers keep their behavior.
- **Unknowns:** lock contention, process-exit release and descriptor inheritance;
  verify these against the real filesystem rather than a mock.
- **Undo:** additive API and empty lease files only; revert the code. Never
  unlink lease files while another process might have them open.
- **Execution:** solo, following the protocol approved in F08.1. First verify
  `File::try_lock` contention/error semantics, then expose `SourceLease` and
  test independent handles, child processes, process death and child inheritance.
- **Checks:** scoped test, format and clippy for `omni_utils` and
  `omni_remote_source`; CI checks platform-specific behavior.
- **Out of scope:** lease-aware materialization and GC (F08.3), atomic refs and
  lockfile publication (F08.4), caller migration (F08.5). These remain separate
  reviewable changes rather than making the primitive imply GC protection today.
- **Escalation:** a store-layout migration or change to materialization/pruning
  moves this beyond the primitive slice and needs its own plan.

## Decisions

- D2: lease files are never unlinked. Their existence retains nothing; only an
  acquired OS lock protects a checkout.
- D8: consumers can share a lease with `Arc<SourceLease>`; the last owner releases
  the lock. A lease is retention coordination only, not permission.
- Expose construction as a documented low-level protocol operation, not a safe
  way to protect an already-returned checkout. F08.3 must acquire it before
  checking completeness or while holding the remote lock during publication.

## Verification and limits

- Real-filesystem tests cover shared readers, exclusive contention, independent
  pins, last-`Arc` release, inert orphan files, invalid path segments and I/O
  errors distinct from contention.
- Child-process tests cover independent handles, forced process death and
  non-inheritance by a spawned child. Handshakes and waits are bounded.
- Linux: `cargo test -p omni_utils -p omni_remote_source` passes (87 tests).
- Scoped library clippy, lease-test clippy and format checks pass. The broader
  `--all-targets` clippy run is blocked by a pre-existing `let_and_return` lint
  in `omni_remote_source/src/manager/tree.rs`'s test helper.
- Windows delete-while-held has a platform-gated test; it cannot be run locally.
  Platform behavior remains subject to CI. Network filesystems with unreliable
  advisory locks remain unsupported, as for the existing remote lock.
- Undo requires no data migration: these APIs are additive and lease files are
  empty. F08.3 must settle the store `VERSION` compatibility decision before
  claiming protection against older omni versions.

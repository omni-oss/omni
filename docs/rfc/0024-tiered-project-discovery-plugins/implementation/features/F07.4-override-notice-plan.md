### 2. Crate placement

The notice lives in `omni_configurations` (the composition boundary), not `omni_task_executor`, because the counts come from `FieldOverride` and `omni_task_executor` depends on `omni_configurations`, not the reverse. It adds the `composition` code prefix (`omni_codes::prefixes!("composition")`). No notice type is added to `omni_task_executor/src/notices.rs`.

## Design

```rust
/// Plugins overrode each other's configuration.
#[derive(Notice)]
#[notice(
    code = "composition.plugin_override",
    level = info,
    message = "{fields} field(s) in {projects} project(s) were overridden by a later plugin"
)]
pub struct PluginOverride { pub fields: usize, pub projects: usize }
```

Not `essential`. Same shape as `cache.dependency_demoted`: counts only, no values, no ids, no paths, no field names.

Counting rule, over `Composed::overrides`:

- A record counts when `!masked_by_explicit` and `overridden` is not empty. (Records already exclude coalesced equal values and additive lists, per F07.3, so those raise nothing.)
- `fields` counts distinct `(root, field)` pairs: a `cache.enabled` that has both an `Emitted` and an `Applied` record counts once, and `env.vars.A` and `env.vars.B` count twice.
- `projects` counts distinct `root` values.
- No qualifying record: `None`, nothing is raised.
- A fileless contributor (no file) counts exactly like a file-backed one: the notice never needs a location.
- `masked_by_explicit` records are not counted, which follows the F07 text: the notice is silent when an explicit layer decides the field, while F07.5 and provenance still list the contributors.

Known limits carried from F07.3, restated here so the notice does not overclaim: lists inside `meta` are never compared, an explicit task that inherits `cache.enabled` through task `extends` is not seen by `masked_by_explicit` (so the notice may count an override an explicit layer in fact masks), and same-key task fields other than `cache.enabled` carry no records. The notice counts only tracked fields (`description`, `env.vars.*`, `meta.*`, `cache.enabled`, `cache.key.defaults`, `output_logs`).

`omni_codes::prefixes!` lists `composition`. Commit 1 also adds a `composition` row to `docs/patterns/diagnostic-prefixes.md` (required by `linked_prefix_owners_are_documented`); that file joins the diff allowlist. Applied-tier records (authored declarations a plugin's activation applied) count, so "by a later plugin" includes applied values; the message stays as pinned.

| Group     | Cases                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

Registry: the code is registered as a notice, level info, not essential.                                                                                                                                                                                               |

## Risks and rollback

- A published notice code is a stable name; changing it later is a break. Pin it in the registry test (done above).
- Overcount from the `extends` limit. Documented; counts only, so the effect is an extra info line.
- Rollback: delete `notices.rs`, the method, the dependency, the registry line and the `composition` row in `docs/patterns/diagnostic-prefixes.md`. Composition is untouched.

## Out of scope

Raising the notice from a run (needs a production caller), per-field or per-contributor detail (F07.5 for `cache.enabled`, P12 for the rest), the duplicate-final-project-name check (stays an error), plugin output validation, any change to `compose_ordered` or cache keys.

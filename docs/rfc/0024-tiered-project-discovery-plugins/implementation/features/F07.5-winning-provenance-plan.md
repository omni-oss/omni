## Decisions requested

### 1. Output shape

Add one nested object per inspected task, identical in text, `--json` and MCP (all three read `InspectedTask`):

```json
"cache_enabled_provenance": {
  "scope": "task" | "project" | null,
  "declared_by": "<contributor id>" | null,
  "file": "<workspace-relative path>" | null,
  "overridden": [ { "contributor": "<id>", "file": "<workspace-relative path>" | null } ]
}
```

- `scope`: the level that decided `cache.enabled`. From the source for authored decisions (`task-explicit` gives `task`, `project-explicit` gives `project`) and from `FinalizedProject::task_cache_enabled_scope` for `plugin`; `null` for defaults and host fallbacks.
- `declared_by`: the contributor id when the winning declaration's origin source is `DeclarationSource::Contributor`; `null` otherwise (authored files, fileless, fallbacks).
- `file`: the workspace-relative declaring file (the value `InspectionNode` already carries for contradictions; it is new per-task output); `null` for contributor, fileless and fallback decisions.
- `overridden`: earlier contributors whose same-tier, same-scope value differed from the winner, in contributor order. Id plus declaration location: never values, never file contents. `file` is set only when the contributor's overridden declaration came from an applied authored file (the `Applied` tier, `DeclarationSource::File`); a plugin-emitted (`Emitted`) or fileless declaration has `file: null`, because a plugin has no file. The F07 spec's "declaration locations" is met to that extent; locations for non-`cache.enabled` fields wait for P12, because `ProjectLayer` leaves carry no per-leaf origin.
- The existing `cache_enabled_source` (tier) stays as is.

| Option                                                                           | Verdict                                                                                                                                                                                          |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **A. Always emit the object (recommended)**                                      | Stable shape (F09: "stable field names"). The F09 JSON shape pin test and the MCP result test are updated for the added field; this is additive and no cache key or non-inspection golden moves. |
| B. Omit the object when it carries no information (`serde(skip_serializing_if)`) | Leaves every existing inspection snapshot untouched but makes the shape conditional.                                                                                                             |

**Recommendation: A.** Narrowing to confirm: locations exist only for applied-tier `cache.enabled` declarations (the only ones with a file); and this slice is independent of F07.4 code, deviating from the spec's stated dependency order. Please confirm that updating the F09 inspection snapshots for one additive field is acceptable; B is the fallback if you want the F09 pins untouched.

### 2. Where `overridden` comes from (includes recording declaration locations)

**Location records are part of this slice, as their own commits.** F07.3's `FieldOverride` records ids only, so this slice adds the locations. To avoid changing the `FieldOverride` struct (the F07.4 thread builds synthetic `FieldOverride` literals in its tests; a new field would break them), the locations travel beside it: `Composed` gains `override_locations: Vec<OverrideLocation { field: FieldPath, tier: OverrideTier, contributor: ContributorId, origin: Arc<Origin> }>`, one entry per overridden contributor of a `cache.enabled` record (when one contributor has several declarations for the same scope and tier, the last whose value differs from the winner's, with a test), taken from that contributor's `EnabledDecl::origin` in `overrides::compute` (the origin is already in hand there; no values). `FieldOverride`, `FieldPath`, `OverrideTier`, `compose_ordered`'s signature and every F07.3 test stay as they are; `Composed` is built only in `ordered.rs`. If the F07.4 PR merges first, rebase; the two PRs touch different parts of `overrides.rs` (F07.4 does not edit it).

F07.3 returns `Composed { layer, overrides }`, and `FinalizedProject` does not carry overrides. Plan: `FinalizedProject` gains `task_cache_enabled_overridden: Map<task, Vec<OverriddenDecl { contributor: ContributorId, file: Option<Arc<OmniPath>> }>>`, empty for all explicit-only input, filled by a pure `attach_cache_enabled_overrides(&mut FinalizedProject, &[FieldOverride], &[OverrideLocation])` (the caller splits `Composed` without cloning, since finalizing consumes the layer; `file` is the `File` path of the origin, `None` for contributor or fileless origins). For task `t` the attached ids are those of the records whose `(field, tier)` equals the decision's own: `TaskCacheEnabled(t)` or `ProjectCacheEnabled` by `task_cache_enabled_scope` (plugin) or by source (`task-explicit`, `project-explicit`), with tier `Emitted` for a plugin decision and `Applied` for an authored one. The attribution rule is exactly: `record.root == the task's project root && (field, tier) == the decision's && !record.masked_by_explicit`. Every other record, including every masked one, is not attributed, because an explicit layer (or higher tier) decided. **Known limit, restated from F07.3:** an explicit task that inherits `cache.enabled` through task `extends` is not seen by `masked_by_explicit`, so an Applied record may be attributed to a decision an explicit layer actually made. A test pins today's behavior; the plan does not skip attribution for explicit replay decisions. A record is attributed to every task whose decision it matches (a project-scope record reaches each task that inherits it).

| Option                                                                | Verdict                                                                                                                                                  |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. Field on `FinalizedProject` plus the pure attach (recommended)** | The extractor already reads `FinalizedProject`; no new channel. Struct-literal and `..`-less destructuring callers break (same migration note as F07.3). |
| B. Carry `Composed` into the context                                  | Needs a production caller that does not exist; widens `omni_context` for nothing.                                                                        |

**Recommendation: A.** Narrowing to confirm: with no production caller, a real run reports an empty `overridden` list. The tested behavior is the plumbing with synthetic composed input.

## Design

- `omni_configurations`: `task_cache_enabled_overridden` and `attach_cache_enabled_overrides` as above; ids come from `FieldOverride::overridden`, files from `Composed::override_locations`. `FieldOverride` carries no values, so none can leak.
- `omni_context`: the extractor builds `cache_enabled_provenance` (a `ProjectDataExtractions` field with `#[new(default)]` and `#[serde(skip)]`, like `cache_enabled_files`, so the serialized extraction and every `::new` caller are unchanged; a test asserts it is absent from the serialized output)
  as `Map<project, Map<task, CacheEnabledFacts>>` from `FinalizedProject` (source, scope, `task_cache_enabled_origin` for the contributor id, the existing file, overridden ids), exposed as `LoadedContext::cache_enabled_provenance(project, task)`. Existing `cache_enabled_files` is left alone.
- `omni_task_executor`: `InspectionNode` gains the provenance; `InspectedTask` gains `cache_enabled_provenance` (`#[serde(default)]`, so older serialized inspections still read). `inspect_nodes` copies it. Non-executing: no new context load, no `enabled` evaluation, no command or environment substitution; the data is configuration read at load time.
- Ownership: the wire type `CacheEnabledProvenance` (and `OverriddenContributor`) lives in `omni_task_executor` (`cache_inspection.rs`). `omni_context` stores an internal `CacheEnabledFacts { scope: Option<CacheScope>, contributor: Option<ContributorId>, overridden: Vec<OverriddenDecl> }` with no serde; `nodes_from_plan` converts it, stripping `context.root_dir()` from the winning file and from every `overridden[*].file` exactly as it does today, and renders `scope` as `"task"`/`"project"` strings (no serde added to `CacheScope`).
- `omni_cli_core` text: `app: eligible (tier: plugin, scope: task, declared by native, overridden: frontend)`; file shown as `, file: <path>` when present; each overridden entry is `id` or `id (path)` when it has a file; nothing printed for absent parts. Paths are the same workspace-relative paths F09 prints today.
- MCP: no code change beyond what `InspectedTask` gives; the result model test is updated.
- Redaction: ids and workspace-relative paths only, as F09.
- Scope: `cache.enabled` only. Other tracked fields wait for P12; the docs say so and no claim of field provenance is made.

## Cache keys stay identical

The F09 inspection and MCP snapshots change by the added field only (decision 1). `CACHE_KEY_VERSION` stays 1. Stop rule: any key golden that moves reverts the slice and rescopes under `docs/patterns/cache-keys.md`.

## Risks and rollback

- Additive JSON field on every task: consumers that reject unknown fields break. Pre-v1; note it in release notes.
- A wrong attribution would name a plugin that did not matter. Covered by the match-by-scope-and-tier rule and the masked and applied tests, except the pinned `extends` limit of decision 2. `FieldOverride::root` and `FinalizedProject::dir` must be the same path form (a test composes with both); a caller passing a different form would silently get an empty list. Every `InspectedTask` struct literal (including `omni_mcp_core` and `omni_api` tests) is updated.
- Rollback: revert commits 3 to 1a together, and revert commit 4's docs (provenance guide, F07 and F09 status lines, README) with them so no doc describes a field that no longer exists. The finalize and cache-key paths are unchanged.

## Out of scope

The notice (F07.4), other fields' provenance (P12), locations for fields other than `cache.enabled` and for plugin-emitted declarations (no file exists), a production caller of `compose_ordered`, `--no-cache` modelling, any cache-key or `CacheEnabledSource` change.

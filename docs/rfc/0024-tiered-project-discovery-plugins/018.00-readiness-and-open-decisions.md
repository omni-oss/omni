## 18. Code-grounded readiness and open decisions

Assessment baseline: repository revision `3ce79ad6`, with static inspection of
the current configuration, context, command, planning, cache, capability and source
code. This is a design/readiness review, not a claim that plugin functionality or
the conformance tests are implemented. The RFC remains draft.

**Assessment:** no fundamental crate-dependency or lifecycle impossibility was
found in the inspected paths. The architecture can support staged implementation,
but the external contract is not implementation-ready as a frozen SDK, and the
native pilots are not release-ready. There are substantial configuration/task
identity refactors and concrete specifications to complete, not just runtime
adapters to add. The gates below apply to their affected work, not every independent
foundation change.

### 18.2 Reconciled findings that need no new decision

Settled by review; each is specified in its normative section and gated in §18.3.

- **Current-code defects (not fixed by this documentation pass):** per-side glob
  omission decodes as empty replacement (`MergeGlobConfig`/`MergeSingleOrMany`), and
  execution-cache reads ignore `cache_enabled` while writes check it. Gates require
  presence-aware side replay and read/write/replay eligibility checks; cache-enabled
  tasks with uncached dependencies follow [§8.3](008.02-execution-cache-semantic-identity.md).
- **Schemas and fixtures:** the first concrete drafts are
  [§6.4](006.04-hook-and-claim-schemas.md#64-hook-claim-and-query-schemas-project_discovery-v0)
  (H01–H24) and [§7.5](007.04-composition-golden-fixtures.md#75-composition-golden-fixtures)
  (C01–C26). They specify expected results; they are not implemented conformance.
- **Claim queries:** a declared, bound inference-dependency slot is the grant, limited
  to the manifest's `publishes`/`consumes` claim types. Denial is an error and the grant
  set is part of cache identity. Observation sees only the activation's accepted roots
  ([§6.1](006.00-hooks-and-lifecycle.md#61-hook-namespaces-and-lifecycle)).
- **Inferred-task caching:** inferred tasks are uncached by the host fallback;
  activation `defaults` (`tasks.cache.enabled`, `key.files`, `key.env`), `apply` and
  explicit configuration opt in through the origin-aware tier order
  ([§7.1](007.00-project-modes-and-apply.md)). Cargo `fmt`/`clippy` inference is deferred.
- **Literal operands versus command expressions:** structured argv alone does not stop
  Tera/environment expansion, so a validation/resolution/serialization/hash audit and
  fixtures are required ([§6.3](006.03-data-boundary-and-literal-values.md)).
- **Collections:** validate envelope shape before list/dictionary decoding can drop
  operator siblings; raw hook output (additive) and composed cache records (may contain
  authored `replace`) use different profiles.
- **Identity:** mandatory per-task effective semantic identity replaces whole-config
  fingerprints, including command-context inputs that raw-command hashing misses;
  internal `*`/`**` pattern callers and project-hash/stale-cache collectors migrate too.
- **Bootstrap and runtime:** pass consistency includes the workspace configuration used
  during bootstrap; lazy startup cannot omit registered singleton hooks; expected
  missing-file reads differ from fatal host errors; size-overflow splitting needs typed
  limit classification.
- **Sequencing:** payload/query specs and fixtures precede final contract types; Wasm
  selection is settled in [§10](010.00-implementation-and-rollout.md#10-implementation-and-rollout).

### 18.4 Practical implementation order and readiness exit

1. Complete the pure contracts and golden fixture inputs for each foundation;
   independent source-type extraction, presence-aware replay and identity/parser
   work can proceed without a Wasm engine. Do not freeze query authorization
   before its dependent contracts are specified.
2. Integrate the shared zero-plugin layer/alias/selection pipeline and semantic
   identity with migration/regression fixtures. Migrate internal pattern callers
   alongside CLI/MCP; a public flag alone leaves current cache planning broken.
3. Land captured-input services, transactional host scheduling, local cache
   primitives/records and native adapters only behind their completed contracts.
   Exercise the full pass, rejected-pass invisibility and ordinary task execution,
   not only mock capability calls.
4. Finalize acquisition/leases and the Wasmtime/WIT bindings and enforcement
   ([§10](010.00-implementation-and-rollout.md#10-implementation-and-rollout)) before enabling external artifacts. Source installation stays separate from
   hook execution; generators/tools do not gain implementations through this work.
5. Release only after the affected gates, adapter coverage and conformance tests
   are demonstrably complete. Static review and Markdown/link checks do not
   establish runtime correctness, containment, cache safety or benchmark results.

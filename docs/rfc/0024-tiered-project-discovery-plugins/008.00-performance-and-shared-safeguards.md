## 8. Performance is a contract

“Must not tank performance” cannot mean that arbitrary code costs nothing.
It means disabled plugins cost effectively nothing, unchanged work is reused,
and enabled work has measurable limits rather than unbounded startup cost.

### 8.1 Shared safeguards

- One shared walk and file-read cache; no full repository traversal per plugin.
- Static marker filtering before loading a runtime. Batch requests and lazy
  runtime initialization; reuse an instance within a command or MCP process,
  with private state limited to [§6.1](006.00-hooks-and-lifecycle.md#61-hook-namespaces-and-lifecycle)'s discardable, observationally transparent
  optimizations. Authoritative semantic state stays in host-owned partitions.
- A bounded worker pool, cancellation propagation and host-wide limits in
  addition to per-plugin limits. Many small invocations must not multiply a
  nominal per-call budget into an unlimited discovery phase.
- Use bounded batches, not one invocation per root and not one unbounded
  whole-workspace request. Amortize dispatch and external marshalling costs
  without letting request construction, serialization, decoding, snapshot
  duplication or peak memory erase the benefit. Bound batches by request bytes
  and estimated input/output/state cost as well as root count; a few large
  roots can cost more than many small ones. Keep queued and in-flight bytes
  bounded across concurrent batches. Batch sizing is host-owned and must not
  affect successful normalized results or stage transaction semantics. Resource
  failures, especially deadlines, are not promised to be schedule-independent.
  Separate per-root logical contribution/state/count limits from per-batch
  transport limits. For attributable aggregate size overflows, the host may
  deterministically split a batch and retry smaller batches against the same
  stage-start state and captured input view. Bound split depth/attempts and charge
  all attempted work to unchanged command-wide budgets. An individually oversized
  root fails with a root-specific diagnostic; do not split/retry arbitrary traps,
  permission denials, malformed output or timeouts. Failed oversized attempts
  publish nothing, and successful smaller batches still require full stage/pass
  acceptance. This host scheduling recovery is distinct from [§17.2](017.00-review-findings-and-prerequisites.md#172-frozen-facts-do-not-imply-frozen-filesystem-inputs)'s default-off
  whole-pass restarts for concurrent input changes.
- Bound file reads, bytes, candidate count, output bytes/project/task count,
  recursion and notices. Validate output before expanding it into graph state.
- Cache inferred fragments separately from final explicitly composed projects.
  Key by host protocol/build, plugin artifact/module closure, options,
  contributor ids and declared-input scopes. Validate previously observed input
  fingerprints through [§8.2](008.01-inference-cache-and-storage.md#82-shared-storage-separate-task-and-inference-caches)'s two-step lookup, rather than hashing every file a
  declaration could permit before lookup. Track missing files and
  scoped directory membership so creation/deletion also invalidates results.
  Input scope declarations are part of the key; no untracked reads are allowed.
- Preserve existing explicit file/extension-closure cache inputs and add the
  per-task effective semantic fingerprint below. A plugin task change must not
  reuse an old execution cache entry merely because no explicit file changed.
- No background inference for commands that do not need projects. Long-lived
  MCP state must invalidate on input, option and activation changes, including
  disabling a plugin or editing a local bundle.
- Reuse a cached hook result only when its request, incoming state and all
  observed inputs/snapshots match. Cached state alone does not justify skipping
  a hook: cross-root resolution also depends on the frozen root snapshot.
